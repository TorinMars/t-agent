# The same page from any engine

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

The same person opening the page of T01 and the page of K01 sees the same order, the same defaults and the same labels everywhere. The one difference left is the small "This machine" label (and the "Local" pill) on the page's own row of the device list in Settings → Devices, and "This device" under its own tab in the Settings tab row, because those say which machine a per-device setting is saved on. The rule behind it: "One experience on every device and engine" in `AGENTS.md`. Mockup: EntrySame.

**Devices in one order** (`scripts/h5-shell/device-order.mjs`, `orderDevices` / `compareDevices`, pure). By name, numbers in names by value ("M2" before "m10"), any case, in a fixed locale (`en`, so a phone in Chinese and a computer in English agree); then by the engine's instance id (two devices with the same name); the page's own source key (`local`, `remote:7`) only last, for a device without an instance id. "This machine" has no place of its own. An older server without an engine name is placed as "This machine". One helper for every place:

- h5.js sorts its services with it (`inOrder`, through `H5UI.orderDevices`, after every read of `/api/remote-servers` and of this machine's name): `sources`, so `listedSources()`, so the task list (the tasks not in the shared order yet, and the whole list on an older server without one), "Create on" of a new task, the services of the mind map list, the T-Attention engines (`attentionEngines`, the engine blocks inside a group, the "on" choice).
- Settings → Devices: the device list (`Engines.jsx`: the rows before and after this machine's row) and "Show in task list" (`ShownDevices`).
- The Settings tab row (`tabEntries` of `settings-tabs.mjs`): Shared, then every device by name, this one among them.
- "Visible to" (h5.js `askVisibility`): the linked machines by name (the server answers oldest link first).
- The Environment table (`orderColumns` of `environment-compare.mjs`).

**Labels.** `deviceParts` / `deviceText` / `DeviceName` (`common.jsx`) name this machine by its engine name only; the "· This machine" hint is drawn when asked (`hint`), which only the device list row of Settings → Devices does. So "Create on", the engine tags and their titles, the session switcher, the T-Attention "on" choice and "Show in task list" read the same on every page. Dialogs and menus of a task name its device beside the title whenever more than one device exists, this machine's tasks too (h5.js `serviceOf`; with this machine alone none). A T-Attention reminder names the engine of every item while more than one engine is listed (`remind` in `attention-feed.mjs`), not only of another engine's.

**"Create on"** (the New task dialog, `TaskDrawer.jsx`, and the mind map view, `scripts/mindmap/app.js`). It starts on the machine a task or map was last made on: the shared page state key `h5-create-on` (an instance id on the server, this page's source key on the page, through the `CODECS` of `public/js/page-state.js`; the same on every device and engine, [shared-page-state.md](shared-page-state.md)), written when a task or map is made and there was a choice. Without one, the first machine in the one order; never the page's own engine. The New task dialog says "The machine you chose last time" under the select while that remembered machine is shown (`#h5-new-task-on-help`). A machine that is offline or hidden falls back to the first one left.

**T-Attention: the engine of a new task** (`QuickAdd` in `Attention.jsx`, `h5-attention-add-on`). The one chosen last, else the first in the one order. This machine is stored by its key like any other (it used to be stored as "nothing", which every page read as itself).

**Mind maps in one list** (`renderList` in `scripts/mindmap/app.js`; [mind-maps.md](mind-maps.md)). The maps of every listed service in one list, the last edited first (`updated_at`; on a tie by the order of devices, then by id), each row with its engine tag (`.mm-row-tag`: the task list's tag, the name cut to 8 characters in the colour of the instance id, `tagColor` / `shortName` of `task-order.mjs`) when more than one service is listed. No group per service. A service that cannot list its maps now has one line under the list (`.mm-source`, `data-state` `loading` / `offline` / `error`): its name and "Loading...", "Offline" or the error with Try again. h5.js passes each service's name (this machine's engine name, not "This machine") and instance id.

**What still treats this machine specially, and why** (the audit of `LOCAL` in h5.js and the shell; none of it changes what the person sees between two engines' pages):

- The session a window opens at start (`h5-source`, `h5-task:<source>`): per browser by design ("browser" in the key audit of [shared-page-state.md](shared-page-state.md)): it decides the first requests before any answer. The session last looked at anywhere is the first of the shared Recent list.
- No task shown: `source` is this machine internally (`selectTask(LOCAL, null)`); nothing is shown for it.
- Feeds: this machine's activity stream is opened first (`syncFeeds`), and only it asks for the shared page state (`?state=1`): the page's engine is the one that pushes the state to it. Connection budget, not presentation.
- A bare task id means a task of this machine (T-Attention's way back, `?openChat=`): link formats of the page's own engine.
- Capabilities: this machine can always archive, sort sessions and read any path; a remote engine says so in its `/info`. The same answer once both run the same version.
- "Visible to" is offered only on the page's own engine's tasks: who can see a task is decided by the engine that owns it, and a linked engine deliberately has no route to read or change it (`test/task-visibility.test.js`, "no such route under /v1"). On every page the rows are by name.
- The default folder hint of a new task is shown only for this machine (`effective_work_dir` of `/auth/me`); a remote engine gets the generic line. A task made through the Engine API goes under that engine's `TASKS_BASE_DIR` (`~/tasks`), not under the person's working directory setting there, so its working directory would be the wrong hint. Making both the same is a change of `/v1/tasks` (not done).
- The Settings tab chosen at first without a Shared tab is this device's (it holds every part then); the chosen tab is per browser.
- The device list of Settings → Devices: this machine's row has Restart, its version and the "Local" pill; the other rows have Check, Update, Edit and Remove. Those are what can be done from here, not an order or a label.
