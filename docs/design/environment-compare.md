# Environment compare

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

**Environment** (Settings → Devices) is one table of the tools agent sessions rely on: a row per tool, a column per machine (this one and every linked device). A version that differs is orange, a missing tool red, and the install hint of the environment check is listed under the table. The goal is the rule "One experience on every device and engine" in AGENTS.md: a session should find the same tools whichever engine it runs on, and the person should see where that is not true without opening each machine.

**The tools list** (`services/environment-check.js`, `tools()` of the same service as the full check, so it uses the same finders and hints). Each machine answers `{ checked_at, platform, tools: [{ id, name, status, value, fix }] }` for, in this order: Node.js (the `node` of the sessions' PATH, else the Client's own), git, Claude Code, Codex, OpenCode (the `opencode` of the sessions' PATH or `~/.opencode/bin`; optional), tcli (`scripts/tcli.js` of this install, which has no version of its own: shown as "ok"), Shell (the first of `/bin/zsh`, `/bin/bash`, `/bin/sh`, as `routes/terminal.js` picks it), Swift (Mac app) (macOS only; `xcode-select -p` is asked first, so a Mac without the developer tools never gets the system's install dialog; elsewhere `not-needed`), pm2. `status` is `ok` (`value`: the version number found in the tool's answer, or a name such as `zsh`, or `''`), `missing` (`fix`: the hint of the check), `not-needed` or `unknown` (the probe threw or took longer than the check's 15 s). The answer is kept for 10 minutes (`TOOLS_TTL_MS`), and two reads while one runs share it. All texts the list can show have Chinese in `public/js/i18n-zh-server.js` (`test/environment-i18n.test.js`).

**Routes.** This machine's page: `GET /api/environment/tools` (the kept answer) and `POST /api/environment/tools` (probe again), behind the browser session and the same-origin gate (`routes/environment.js`). A linked device: `/api/device-settings/<id>/environment/tools` (GET and POST, 30 s), forwarded over the service link to `/v1/device-settings/environment/tools` of that device (the allowlist of "Settings of a linked device" in [linked-device-settings.md](linked-device-settings.md); only the tools list, never the full check, which holds the page's address and settings). The device lists `environment:tools` in `/v1/info`; `GET /api/device-settings/devices` passes it on as `environment` (true, false, or null while unknown).

**The page** (`scripts/h5-shell/EnvironmentCompare.jsx`, model `environment-compare.mjs`; in the Settings chunk, nothing in the first screen):

- The part `environment` has the scope `all` in `settings-tabs.mjs`: the same table in Shared, this device's tab and every linked device's tab (under "Show in task list" in Shared, under the device list in a device tab).
- Columns are ordered by name (numbers by value; the shared helper `device-order.mjs` of every device list, [entry-symmetry.md](entry-symmetry.md)), so T01's page and K01's page draw the same table; machine names and versions are `translate="no"`.
- The newest version is the reference and every other found version is orange; for a value that is not a version (a shell name) the most common one is the reference. A machine without the tool is red "not installed" with "K01 · Codex: <hint>" under the table. "not needed" and "unknown" are grey and count as nothing.
- A column that cannot tell says so under the machine's name: "Offline" (not online, or the link answered `REMOTE_OFFLINE` / `REMOTE_TIMEOUT` / `ENGINE_OFFLINE`), "Update K01 first" (no `settings:device`, no `environment:tools`, or 501 `DEVICE_SETTINGS_UNSUPPORTED`), "Could not be read" (another error). Such a device is not asked when the device list already says it cannot answer.
- Under the table: the summary ("2 differences · 1 missing", "The same on every machine") and "Check again", which POSTs to every machine; old values stay in the table until the new ones arrive.
- The Devices row of the group list shows the same summary in the warning colour (on a phone under the row's second line). For that the lists are read when the sheet opens, after the device list and only while a device is linked (one machine has nothing to compare, and the sheet then reads no group's data before it opens) (cheap: each machine keeps its answer for 10 minutes), and again when the group opens if the last read is older than a minute.
- On a phone the table scrolls sideways inside its card with the first column fixed (`position: sticky`, with the card's own colour and elevation overlay); two machines fit at 390 px without scrolling.

**Limits.** Nothing is remembered across page loads (each machine's own 10-minute cache does that). Only linked devices with a service link take part; a plain remote engine has no column. An offline device shows no last known values.

Tests: `test/environment-check.test.js` (the tools list: versions, missing tools with hints, Swift off macOS and without the developer tools, a hanging probe, the cache), `test/environment-routes.test.js` (GET / POST, session and origin, the linked devices' router), `test/device-settings.test.js` (allowlist, the peer route, `environment` in the device list, forwarding), `test/h5-environment-compare.test.js` (the model), `node scripts/test-h5-environment-browser.cjs` (1440: the mockup's table, colours, hint, the Devices row, the same table in every tab, Check again; devices that cannot tell; 390: sideways scroll with the first column fixed; Chinese).
