How strongly the page's own keys vibrate on each device, chosen in Settings → Keyboard (the Settings page itself: "Settings, Devices and Update" in [page-files-and-settings.md](page-files-and-settings.md)).

## Vibration on key taps

**Vibration on key taps** (Settings → Keyboard, `#h5-sec-key-haptics`; `scripts/h5-shell/KeyboardSettings.jsx`, model `key-haptics.mjs`, played by `key-feedback.mjs` `tick`; design confirmed 2026-11-24). How strongly the page's own keys vibrate on this device: every key of the page's keyboards (`Osk.jsx` `Keyboard`: the terminal's and the Learn page's) and every key of the key row of the bottom bar (`#h5-keys`, `Terminal.jsx` `KeyBar`: Esc, the arrows, Enter, Backspace, Tab, Ctrl, Alt, Home ... ^C), on the press (pointerdown), once per press (a held Backspace ticks once, not on its repeats). Not the tool row, not the system keyboard (it has its own setting in the phone). A setting that takes effect at once: no Save button. What the part shows follows what the device can play (`hapticKind`, found once per page):

- `vibrate` (`navigator.vibrate` on a touch screen: Android): an MD2 radio list (`#h5-key-haptics`, 56px rows, the radio at the start, the label and a note, the chosen row in the primary colour's selected overlay): Off "No vibration" (0 ms), Light "A short tap (as today)" (8 ms, the default: the tick the keys played before), Medium "A firmer tap" (15 ms), Strong "A clear buzz" (28 ms). Choosing one plays it once (inside the tap); a note says where it plays; "Try it" (`#h5-key-try`): q w e Esc Enter Backspace, keys in the look of the page keyboard (`Osk.jsx` `KEY`) that tick with the chosen strength and type nothing.
- `switch` (no Vibration API, but WebKit's `<input type="checkbox" switch>` on a touch screen: iPhone and iPad from iOS 17.4): one switch row "Vibrate on key taps" / "A light tap, as the system plays it" (`#h5-key-haptics-switch`, on by default; on stores Light, off stores Off; turning it on plays the tap once), and the line "iPhone lets a web page play only one kind of tap, so there is no strength to choose here."
- `none` (no touch screen: a computer; desktop Chrome has `navigator.vibrate` but nothing to vibrate, Safari on a Mac has the switch but no haptic): "This device cannot vibrate" (`#h5-key-haptics-none`) and a line saying phones and tablets choose it here. The group stays in the list on a computer, so every device shows the same groups in the same order ("One experience on every device and engine" in `AGENTS.md`: a feature that cannot work here says so).
- Storage: `h5-key-haptics` in this browser (`public/js/local-keys.js`, category hardware: vibration is a property of the device in the hand, so a phone and a tablet each keep their own; "Key audit" in [shared-page-state.md](shared-page-state.md)); the value is `off`, `light`, `medium` or `strong`, anything else (nothing stored, blocked storage) is Light. It never goes to the server. `tick` reads it at each press, so a change applies at once. The Section title uses the cards' subtitle1 like every other part of Settings (the mockup drew it as an overline), and the "This device only" pill follows `ScopeLabel` (shown only while a device is linked, like every other pill).
- Tests: `test/key-haptics.test.js` (strengths and durations, the stored value and its default, `hapticKind`) and `node scripts/test-h5-key-haptics-browser.cjs` (390 x 844 touch with a recorded `navigator.vibrate`: the group and its four choices, choosing plays once, the key row and the keyboard vibrate with the chosen duration on press and once for a held key, the tool row does not, Off stops it, the value survives a reload and goes in no request, another browser starts at Light; an iPhone-like page: the switch, ticks only while on; a computer: "This device cannot vibrate"). Not tried on a real Android phone or iPhone: vibration and the switch haptic are only checked as calls.
