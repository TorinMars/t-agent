# Settings of a linked device

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

The per-device parts of the settings sheet ("This device only") can be read and changed for a linked device from this device's page. Code: `routes/device-settings.js` (allowlist, the peer router, the page router), `services/work-dir.js` (the working directory, shared with `PUT /auth/settings`), the page side `scripts/h5-shell/DeviceTarget.jsx` and `device-target.mjs`. Shared parts are one set already (settings sync) and Telegram has its one sender, so neither goes this way.

**Capability and peer routes** (on the device that is changed). `/v1/info` lists `settings:device`. `/v1/device-settings/<path>` takes `requireEngineAuth('engine:admin')` and then a token issued for a live service link (`linkForToken`, not revoked); any other Engine token is 403 `LINKED_ONLY`, as for `/v1/settings-sync`. Before any handler the method and the path must be on the allowlist below, exactly as written (anchored patterns, case-sensitive; `..`, `%2e`, a trailing slash, a query or another method do not match): anything else is 404 `DEVICE_SETTING_NOT_ALLOWED`. A body is cut down to the listed fields of a plain object. The handlers are the page's own routers mounted again with the session and same-origin checks replaced (`createPeerFsSettingsRouter`, `createAgentSkillsRouter`, `rule-sync` `createBrowserRouter`), so the peer answers what its own page gets. `<path>` is the page's path without its leading `/api`:

| Method and path | Page route | Body fields |
| --- | --- | --- |
| `GET /auth/me` | `/auth/me` (answers only `{ work_dir, effective_work_dir }`, never the account or access mode) | |
| `PUT /auth/settings` | `/auth/settings` | `work_dir` |
| `GET`, `PUT /peer-fs/settings` | `/api/peer-fs/settings` | `enabled` |
| `GET /agent-skills`, `POST /agent-skills/<name>/install`, `POST /agent-skills/t-attention/remove-old` | `/api/agent-skills` | none |
| `GET`, `PUT /rule-sync`; `POST /rule-sync/{create-shared,push,reset-source,remove-import,dismiss-local-changes}`; `GET`, `PUT /rule-sync/shared` | `/api/rule-sync` | `role, codex, skills, claude_settings_keys, keep_local`; `content, base_revision` |
| `GET`, `PUT /attention/widget/settings` | `/api/attention/widget/settings` | `enabled` only: the window language is shared |
| `GET`, `PUT /device-tier` | `/api/device-tier` (see "Device tier" below) | `company_computer` |
| `GET`, `POST /environment/tools` | `/api/environment/tools` (the tools list only, never the full check; see [environment-compare.md](environment-compare.md)) | none |

The window's router for a peer is `peerSettings` of `routes/attention-widget.js` (registered from `server.js`, where the launcher is made): the same answers, but it never notes the page language, which belongs to that machine's own page. Without it the two paths are 404 `WIDGET_UNAVAILABLE`. No route on the list holds a secret: OSS, translator and speech keys, Telegram, CLI and remote tokens, the account and access mode, restart and PM2 are not reachable, and the answers are the masked ones a page gets anyway. The tunnel carries `/v1/device-settings` without any change to its rules; the mount is in the reviewed list of `test/task-visibility.test.js` (no task in it).

**Device tier** (`services/device-tier.js`, `routes/device-tier.js`). Each machine has a "Company computer" flag (low tier), off by default: a machine marked so keeps none of the person's own data for long (today the English learning data, the usage data and the mind maps; see "Company computer" in [learn-english.md](learn-english.md), "Merged across linked devices" in [usage-data.md](usage-data.md) and "Mind maps on every engine" in [mind-maps.md](mind-maps.md)), while the shared settings and the site library still sync to it as before. It belongs to the machine (device scope, never in the settings sync): `system_state` `device_tier_v1` `{ company: true }`, no row when off. It is told to the peers in `GET /v1/info` (`company_computer: true|false`, capability `device:tier`). Routes: this device's page `GET /api/device-tier` → `{ company_computer }`, `PUT /api/device-tier { company_computer: true|false }` → `{ company_computer }` (400 `VALIDATION_FAILED` otherwise); a linked device's page the same through `/api/device-settings/<row id>/device-tier`. The page (`scripts/h5-shell/Engines.jsx`, the model in `device-target.mjs`):

- **The switch.** Each row of the device list of Settings → Devices for this machine and for every linked device has "Company computer" (`.h5-engine-company`, an MD2 switch in the row, under "Show in task list" when that is in the row; it takes effect at once), in every tab (the device list is this device's in every device tab; the flag never goes into the settings sync). A remote Engine that is not linked has none, nor has this machine on a server without `GET /api/device-tier`. This machine reads `GET /api/device-tier` when the group opens; a linked device's value is `company_computer` of the device list (`DeviceTarget.jsx`), read again after its `PUT`. The switch shows the new value at once; a failed `PUT` puts it back and the reason is on the row (the server's message, or the words of the error code, as for a rename).
- **The line under it** (`tierCaption`, caption, right-aligned): off "Keeps your personal data, such as learning progress."; on "Personal data stays on T01. Kept here only while no other machine can be reached.", where the home is what the page can tell (`tierHome`): for this machine the first normal linked device that is online, else the first normal one; for a linked device this machine, when it is normal and no other linked device is known to be normal (that one could be the home too). Otherwise "Personal data stays on your other machines. Kept here only while none of them can be reached." A disabled switch says why: "K01 is offline. This can be changed once it is back online." (offline, or not known; the last known value is shown) or "Update K01 first" (`supported: false`, or `company_computer: null` from an online device without `device:tier`).
- **The pill.** A marked machine has an outlined warning-colour "Company computer" pill after its status pill (`.h5-engine-company-pill`, the `Pill` of the Online and Local pills). In the device tabs a marked linked device says "Company computer" under its name in the warning colour, unless "Offline" or "Update K01 first" is said there (`company` of `tabEntries`); this device's tab keeps "This device".

**Page routes** (on the device the page runs on; behind the browser session and the same-origin gate of `/api`).

- `GET /api/device-settings/devices` → `{ devices: [{ id, name, online, supported, company_computer, environment }] }`: the `remote_servers` rows of the owner that have a link that is not revoked (plain remote Engines are left out), oldest first. `supported` is whether `/v1/info` lists `settings:device`, `company_computer` the device's "Company computer" flag from the same `/v1/info` (`null` when it does not list `device:tier`), `environment` whether it lists `environment:tools`: read with a 3 s limit for online rows, kept for 60 s (a `PUT /device-tier` through this route drops the row's entry, so the list shows the change at once); an offline row keeps the last known values, or `null`. No address, token or link id.
- `ANY /api/device-settings/<row id>/<path>` checks the same allowlist (404 `DEVICE_SETTING_NOT_ALLOWED` before anything is sent), that the row is linked (404 `DEVICE_NOT_LINKED`), cuts the body down, and sends it with the link's stored token through `services/remote-client.js` (`tunnel://` included; 15 s, 20 s for the shared rules and the window, 30 s to 60 s for installs, pushes and rule changes). The answer passes as it is. Errors: the peer's own JSON error with its status (for example 409 `RULE_SYNC_SHARED_CHANGED` with `current`, or the working directory's 400); a 401 is 502 `ENGINE_UNAUTHORIZED` and marks the link (`noteUnauthorized`); a plain 404 or a redirect without a JSON error (a device from before this version) is 501 `DEVICE_SETTINGS_UNSUPPORTED` and marks it unsupported; no answer is 502 with the transport code (`REMOTE_OFFLINE`, `REMOTE_TIMEOUT`) or `ENGINE_OFFLINE`.

**Page: the owner tabs.** Under the sheet's title, in its header (so it stays in view while the body scrolls), a row of tabs says what a change belongs to (`scripts/h5-shell/SettingsTabs.jsx`, MUI `Tabs`, `#h5-settings-tabs`, tabs `#h5-settings-tab-<shared|local|id>`; model `scripts/h5-shell/settings-tabs.mjs`; state in `DeviceTarget.jsx`):

- **Shared** (only while the settings sync shares with a linked device, see below), then **every device by name** (the one order of devices, [entry-symmetry.md](entry-symmetry.md)): this device (its engine name from `state.sources`, with "This device" under it; an older server without a name says just "This device") among the linked devices of `GET /api/device-settings/devices`, so the page of every engine shows the same row. A linked device without the feature is a disabled tab with "Update K01 first" under its name, one that is offline and not known is disabled with "Offline"; one that is offline but has the feature can be chosen, says "Offline", and the line under the tabs says "K01 is offline. Its settings can be read and saved again once it is back online." (its calls say so too). The row scrolls sideways when the tabs do not fit, with a 44px scroll button at each end shown while there is more to see (`allowScrollButtonsMobile`; the icon is the library's `treeChevron`, turned for the start). The arrow keys move between tabs (disabled ones are skipped) and Enter or Space chooses (`role="tablist"`, `role="tab"`, `aria-selected`; the tablist is named "Settings for"). Tabs are 48px high; device names are never translated (`translate="no"`).
- **The line under the tabs** says what a change there affects: "Changes here are copied to every linked device" (Shared), "Only this device uses these settings" (this device, next to a Shared tab), "Changes here are saved on this device" (this device without a Shared tab, where it holds every part), "These settings are read and saved on K01". Nothing says a change is copied while there is no Shared tab, and the scope labels are hidden then too (they follow the settings sync, see "Settings sync").
- **When there are tabs** (`tabsShown` of `settings-tabs.mjs`): while `GET /api/device-settings/devices` lists at least one linked device (disabled ones count), or `GET /api/settings-sync` says the sync shares with a linked device (supported and at least one peer, the same rule as the scope labels). The settings sync decides only whether there is a **Shared** tab: with the sync turned off (`SETTINGS_SYNC_ENABLED=false`, the route answers `{ supported: false, ... }`), or supported but with no peer while the device list has a device (for example a linked device too old for the sync), the tabs are this device and each linked device, without Shared. The forwarding of a linked device's parts does not depend on the sync (`settings:device` is always in `/v1/info`, and neither `/api/device-settings` nor `/v1/device-settings` checks it), so K01 can still be chosen. A single machine and an older server (both routes 404) have no tabs: every part is drawn and the per-device parts are this device's, as before the tabs. The sheet therefore reads `/api/settings-sync` and the device list when it opens (no group reads anything before it is opened; after the device list, while a device is linked, it also reads the tools list of every machine, for the summary on the Devices row, see [environment-compare.md](environment-compare.md)); until both have answered once, the sheet is drawn without tabs, so the Shared tab never appears after the others.
- **What each tab holds** (`PARTS` of `settings-tabs.mjs`; a part drawn in a tab is wrapped in `InTab`, a group with no part in the tab stays mounted but hidden, `GroupShown` in `Form.jsx`): Shared — Image and file upload with the tcli switch, Site library, Voice input (with its browser-local "Enable voice input" checkbox, which keeps its "This device only" pill), Translation, the "Settings sync" status line, "Show in task list" (a list of its own here: each device's name and switch, `#h5-sec-task-list-devices`), Notifiers, the Telegram row and page, Rules for all notifiers, the desktop window's language (under the part's name), AI summary. A device tab — Working directory, Agent skills, Browser extension, the device list (without the switches), Link a device, peer file access, Rules and skills sync, Advanced, the setup guide, Reminders, Listeners and the plugin marketplace, the desktop window switch with its status, the agent skill pointer, CLI tokens, Access mode, Authenticator. Account and access is hidden in Shared, Voice and translation in the device tabs. Without a Shared tab, this device's tab draws every part, as the sheet without tabs does (the shared parts are this device's own then, as the route's scopes say), so nothing is out of reach; a linked device's tab holds its per-device parts as above. Language and Log out belong to this browser and are drawn in every tab, outside the tab content.
- **Pills inside a tab:** a scope label whose scope is the tab's says nothing new and is left out (`labelRedundant`); its details line ("Waiting to reach K02", "Changed on K01, 5 min ago") stays, in the same place, as does the Saved and "Copied to linked devices" line. Kept: Telegram's sender in Shared, the voice checkbox's "This device only" in Shared, the setup guide's "Setup guide shown or hidden: Shared across devices" in a device tab (the guide's steps act on that machine, so it is a device part, but whether it is shown is one choice for every device, settings sync group `attention-guide`), and in a linked device's tab the labels that stay "This device only" whichever device is shown (`follow={false}`: reminders, device names, Browser extension).
- **The chosen tab** is per viewer: `localStorage` `t-agent.settings-tab` (`shared`, `local` or the device's row id; every access in try/catch), the first tab at first (Shared, or this device without a Shared tab). A remembered device that is no longer linked goes back to the first tab and is forgotten; one that is linked but cannot be chosen now goes back to the first tab and stays remembered. A remembered Shared tab while there is none shows this device's tab and stays remembered, so it is chosen again once the sync is back. The device chosen in "Settings for" before the tabs (`t-agent.settings-device`) is read once as that device's tab.
- **Opening a part from code** (`ui.actions.openSettings(id)`, settings-target.mjs): the sheet moves to the tab that holds the part — a per-device part opens on this device's tab, whichever device was shown — and then opens the group on it. A whole group stays on the chosen tab when it has parts there, else Shared when it has shared parts, else this device (`tabForTarget`). Without a Shared tab, a shared part or group opens on this device's tab, which holds it then; the missing Shared tab is never chosen. The request is passed to the group only once its tab is shown, and placed once: the person can move to another tab afterwards.

One place decides where a part reads and writes: `useDeviceTarget()` gives `{ device, remote, name, key, api }`, where `api` is the page's `api` with the URL of the device of the chosen tab (`devicePath`: the page path for Shared and this device, `/api/device-settings/<id><path without /api>` for a linked one). Each per-device part is drawn keyed by `key`, so a new tab draws it again and it reads that device's values when its group is open. In a linked device's tab:

- **Read and saved on that device:** Working directory, Agent skills, Peer file access, Rules and skills sync (and its shared rules editor), the desktop window switch with its status. Their pill would say "K01 only" (`ScopeLabel` follows the tab; title "Only K01 uses this. Changes here are saved on K01."), which the tab says already, so it is left out.
- **Not in the tab:** everything shared and Telegram (they are one set, always read and saved on this device and copied by the sync, the window language included).
- **This browser or this page, labelled "This device only"** (`follow={false}`): the reminders, device names (each row of the device list renames its own device already).
- **"Open K01’s own page to change this" instead of the controls** (`LocalOnly`, `OwnPageNote`): Access mode and Authenticator (a window of the local browser, and the account), CLI tokens (a new token is shown once and must not cross), the setup guide and the listeners (they install hooks and open pairing on the machine the page runs on), Browser extension (it pairs with the computer the page runs on), Link a device and the Advanced part (connections of that device). The plugin marketplace is left out (it installs on this machine). The device list stays this device's.

**Known limits.** Plugins installed from the marketplace and the listener pages are this device's only. Restart and updates of another device stay where they are (the device row's Check for updates). The skills, rules and window of an offline device cannot be read. A tab chosen in one browser is not chosen in another. With the settings sync turned off the scope labels are hidden, so a "This device only" label of a part that stays with this browser (`follow={false}`) is not shown in a linked device's tab either. A linked device that is in the settings sync but not in the device list (no link row) has no tab.
