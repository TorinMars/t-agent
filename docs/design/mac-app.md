# T-Agent macOS app

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

## Server and floating window integration

> Code: `services/app-info.js` (app.json, the web addresses, the installed app), `server.js` (`startAppInfo`, at listen time), `routes/system.js` (`GET /api/system/app-info`), `services/frp.js` and `services/ssh-tunnel.js` (`status()`), `scripts/h5-shell/MacApp.jsx` (the Settings card), `widgets/macos/PartB-Actions.swift` (`appOpenLink`, `openPage`, `raisePage`). Tests: `test/app-info.test.js`, `test/attention-widget-open-terminal.test.js` (the app's page counts as a local page), `scripts/test-h5-mac-app-browser.cjs`, the widget's `--self-test`.

The app is a front end only: the web service is the Node server, which keeps running when the app quits, and browsers, phones and linked devices keep using it as before.

**app.json.** The server writes `<data home>/app.json` (data home of `lib/data-home.js`: `TAGENT_HOME`, then `T_AGENT_DATA_DIR`, else `~/.tagent`) once it listens, and again whenever its content changes: it is rebuilt every 60 s (an unref'd timer) and on each `GET /api/system/app-info`, and written only when something other than `updated_at` changed. The write is atomic (a temporary file in the same folder, then a rename) with mode 0600; the file is not deleted on exit (the app tells a running server by `pid` and a health check of `/api/system/version`). A failing write is logged once and never stops the server. Fields:

- `url`: the loopback address the server answers on (`http://127.0.0.1:<port>` when `HOST` is `0.0.0.0`, `::`, empty or `localhost`; otherwise `http://<HOST>:<port>`, IPv6 in brackets).
- `version`: the `app_version` this process runs (read at listen time). `pid`, `install_dir` (the install folder, `lib/data-home.js INSTALL_DIR`).
- `supervisor`: `pm2`, `systemd`, `launchd` or null, from `lib/update-supervisor.js detectSupervisor` (the same proof-based check as Restart). `pm2_name`: under PM2 the `name` that PM2 copies into the environment of its process (else `pm_id`), null otherwise. `launchd_label`: under launchd the job label launchd sets in `XPC_SERVICE_NAME` (the one `detectSupervisor` trusts), for `launchctl kickstart` / `bootout`; null otherwise (the app then defaults to `com.tagent.client`).
- `updated_at` (ISO), and `addresses: [{ kind, label, url }]`:
  - `local` "This computer": the `url` above.
  - `lan` "Local network (<interface>)": `http://<IPv4>:<port>` for each RFC 1918 address of a non-internal interface (`os.networkInterfaces()`), only when the server listens on every interface (`0.0.0.0`, `::`, empty); listening on one LAN address lists only that one (once: it is also `url`); loopback lists none.
  - `remote`: the public addresses the remote-access features know, each only when real and running: "Remote (frp)" `http://<frp domain or server>:<remote port>` while the frp tunnel runs (its `publicAddress`); "Remote (SSH tunnel)" `http://<ssh host>:<remote port>` while the SSH reverse tunnel runs bound on all interfaces of the server (`bindAll`; bound to the server's loopback it is only reachable through a proxy there, which is not known); "Remote (public page address)" the `publicUrl` of the T-Attention notifier rules (the address messages link to). Service links know only the peer's address, not this one's, so they add nothing.
  - Every URL is `http(s)` with a host and without user name, password, query or fragment (`cleanUrl`), so no token can be written; each URL appears once (the first label wins). No tunnel token, key path or other secret is copied.

**GET /api/system/app-info** (browser session, behind the same login and same-origin gates as the other `/api/system` routes; `Cache-Control: no-store`): `{ addresses, app, server: { version, install_dir } }`. `app` is null when the server is not on macOS; otherwise `{ installed, path, version, matches_server }` for `~/Applications/T-Agent.app`, then `/Applications/T-Agent.app` (`Contents/Info.plist` read with `plutil -convert json -o -`, `CFBundleShortVersionString`; an unreadable plist is installed with version null), cached for 30 s. `matches_server` compares with the running version.

**Settings card.** "Mac app" in Settings → Devices (see "Settings, Devices and Update" in [page-files-and-settings.md](page-files-and-settings.md)): read only, no install button.

**Page channel.** A page loaded in the app's WKWebView on the loopback URL is a top-level page of this machine like a browser tab: `services/page-channel.js` and `GET /api/attention/stream?tab=1` key only on the browser session, `tab=1`, a loopback socket without forwarding headers and a Referer without `pane` (a missing Referer counts), never on the User-Agent, Origin or `Sec-Fetch-*` headers. So the app's page gets `open-terminal` from the floating window's Open session; nothing changed on the server for it.

**Floating window.** With T-Agent.app (bundle id `local.t-agent.app`) installed or running (`NSWorkspace.urlForApplication(withBundleIdentifier:)`, `NSRunningApplication`), each T-Agent page the window opens — the `open_path` fallback of Open session, a Working now row or a bubble, a task link that is a page of this T-Agent, the page root of a bubble without a target — opens as `t-agent://open?path=<path, query and fragment, percent-encoded to unreserved characters>`; an address on any other origin (external task links, a notice's external target) still opens in the browser. When the open-terminal POST was delivered but no tab was focused, the running app is brought forward with `t-agent://show`, else the default browser as before. The lookups are injected (`appInstalled`, `appRunning`, `activateApp`) and never the real ones offscreen; see [attention-desktop-window.md](attention-desktop-window.md).
