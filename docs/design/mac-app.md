# macOS app (T-Agent.app)

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

> Code: `apps/macos/*.swift` (the app, entry point `main.swift`; `apps/macos/README.md` lists the files), `scripts/build-mac-app.js` (the bundle). Tests: `test/mac-app-swift.test.js` (compiles the sources and runs `--self-test`).

## Why a shell app

T-Agent is a web service: a Node server that PM2 (or launchd) runs and that updates itself with git. Browsers, phones and linked devices use it. A Mac user also wants it as an app: its own window and Dock icon, a menu bar item that tells whether the service runs, Start / Restart / Stop without a terminal, and links that other programs (the floating window) can open. The app is only that front end. It is a thin native AppKit program with a WKWebView, built with the Command Line Tools like the floating window (`widgets/macos`). It has no Electron and no bundled Node, and it never replaces the server. The web service stays reachable exactly as before: quitting the app never stops it, and the window shows the same service that browsers use.

- Bundle id `local.t-agent.app`, minimum macOS 12, universal (x86_64 and arm64), ad-hoc signed, version = `app_version` of `VERSION.json`.
- The app's text is English only in v1. It has no translation layer (the page inside it is translated as usual); `test/mac-app-swift.test.js` fails on CJK text in `apps/macos`.

## The app

**Finding the server.** The server writes `<data home>/app.json` at every start (`url`, `version`, `pid`, `install_dir`, `supervisor`, `pm2_name`, `addresses`; see the server section below). The data home is `TAGENT_HOME`, then `T_AGENT_DATA_DIR`, then the hidden default `DataHome` (`defaults write local.t-agent.app DataHome <path>`, for a person whose `TAGENT_HOME` lives only in a shell profile, which an app opened from the Finder does not see), else `~/.tagent`. Every field is checked: a missing or broken file gives the defaults (`http://127.0.0.1:3000`, no supervisor), and a bad field falls back to its default while the others are kept. `url` keeps only `scheme://host[:port]` of an http(s) address. An optional `launchd_label` names the LaunchAgent; the default is `com.tagent.client`. app.json is read again before every check, so a new port is picked up (the page loads again at the new address).

**Is it running.** `GET <url>/api/system/version` with a 2 s timeout, no proxy, no cookies. Any HTTP answer counts as running, because the route needs a login, so a 401 also proves the server is there. The version comes from a 200 answer, else from app.json. A state machine (`stepMonitor` in `ServiceMonitor.swift`) has the states checking (launch), running, not running, starting, restarting and stopping:

| State | Next check |
|-------|------------|
| running | 15 s; after one failure again in 1 s, and only two failures in a row count as gone (one failure can be a restart) |
| not running | 5 s |
| starting, restarting, stopping | 1 s; a start not answered within 60 s has failed, and a stop the server still answers 20 s later has failed |

Only one check is pending at a time, and the answer to an older check is dropped.

**Starting at launch.** When the first check finds no server, app.json names PM2 or launchd, and the preference "Start T-Agent when the app opens" is on (default on; in the menu bar menu and the app menu), the app runs the Start command once per app run. The placeholder says "Starting T-Agent…" and the page loads as soon as the server answers. Without a supervisor it does not start anything; the placeholder explains how.

**Window.** One window (it remembers its frame through `setFrameAutosaveName`) with a WKWebView on the server. It uses the default persistent website data store, so the login cookie survives restarts and the person logs in once in the app. The user agent is WebKit's default plus ` T-AgentApp/<version>` (`applicationNameForUserAgent`), so the page and the server can tell the app from a browser. Swipe back and forward is on. Web Inspector can be attached only on macOS 13.3 and newer, and only in a debug build or with `defaults write local.t-agent.app WebInspector -bool true`.
- Navigation (`navigationDecision`): the server's own origin (scheme, host and port) stays in the window. Another origin from the main frame, every `target=_blank` and every `window.open` open in the default browser (the app never opens a second web view). An iframe of another origin loads in place. `about:blank` / `about:srcdoc` and `blob:` load in place, `data:` only in an iframe, and `mailto:` / `tel:` go to their app. Everything else is cancelled, including `file:`, `javascript:` and `t-agent:`.
- Links from the page (`tagentOpen`, `OpenLinkMessages` in `MainWindow.swift`, the pure `linkToOpen` in `URLPolicy.swift`): the web view has `javaScriptCanOpenWindowsAutomatically = false`, so a `window.open` without a click never reaches `createWebViewWith`. A web link that a program in a terminal opened ([open-links.md](open-links.md)) arrives without a click, so the page posts it to the script message handler `window.webkit.messageHandlers.tagentOpen` instead, and the app opens it with the browser opener (`NSWorkspace`). Taken only from a frame of the server's own origin (the page or one of its column frames), only a string of at most 4096 UTF-16 units that is an http(s) URL with a host and no white space or control characters; anything else opens nothing. The handler holds the window weakly (WKUserContentController keeps its handlers).
- Microphone (voice input): `requestMediaCapturePermissionFor` is granted for the server's own origin only, and macOS then asks once for the app (NSMicrophoneUsageDescription).
- File inputs open an NSOpenPanel (multiple files and folders when the input allows them). `alert`, `confirm` and `prompt` show as sheets (the page uses `confirm`).
- Downloads (WKDownload): a response the web view cannot show, or `Content-Disposition: attachment`, or a link with `download`, goes to `~/Downloads`. The name is cleaned (no folders, colons or leading dots), and a taken name gets ` (1)`, ` (2)` and so on. A finished download makes the Downloads stack bounce.
- Keyboard: a program without a nib has no menu, so the app builds the main menu in code. Its Edit menu uses the standard first-responder selectors, which makes Cmd+C / V / X / A / Z work in the page. Cmd+R reloads, Cmd+[ / Cmd+] go back and forward, Cmd+0 / Cmd+= / Cmd+- zoom, Cmd+W hides the window (the app stays in the menu bar and the Dock; a Dock click shows it again), and Cmd+Q quits the app while the server keeps running. No menu item takes Esc, Tab or the arrow keys, so they reach the page and the terminal. WebKit offers other key equivalents to the page before the menu.
- A main-frame load that fails makes the monitor check at once. A web content process that crashed is reloaded.

**Not-running view.** While the server does not answer, the window shows a native view instead of a WebKit error page. It says "T-Agent is not running" and explains that this is the same web service that browsers and phones use. It shows the last error (for example `pm2: command not found`), or the Terminal command when there is no supervisor, and has the buttons "Start T-Agent" and "Try again". It tries again every 5 s. It keeps AppKit controls but follows Material Design 2 for layout (`PlaceholderLayout`): the 8 pt grid (8 between title and text, 24 before the spinner or buttons, 8 between buttons, 32 from the edges, text at most 480 wide), Headline 6 / Body 2 type (20 pt medium title, 14 pt secondary text), system surface and on-surface colors, and one accent on the primary "Start T-Agent" button. While a start runs it shows a spinner instead of the buttons. When the server is back, the page that was open loads again (or the path of a waiting `t-agent://open` link).

**Menu bar.** An NSStatusItem with a template icon drawn in code (a rounded square with a T). The menu is rebuilt from `statusMenuEntries` every time it opens:
- the status line ("T-Agent is running (v2.133.1)" / "T-Agent is not running" / "Starting T-Agent…" …) and "The same web service your browsers use"
- Open T-Agent, and Open in Browser (the page that is open, else the server; only while it runs)
- Web addresses: one item per address of app.json (`label: url`). A click copies the URL, and with Option held the item becomes "Open <label> in Browser" (an alternate item). The list comes from app.json `addresses`, read defensively: only `kind` local / lan / remote with an http(s) URL that has a host and no user or password. A missing label becomes This Mac / Local network / Remote. The list is sorted local, lan, remote, without repeats, at most 12, and is the server's own address when empty.
- Start (only while not running; without a supervisor it explains how), Restart and Stop (only while running under PM2 or launchd). None of them is enabled while a command runs.
- Start T-Agent when the app opens (a checkbox), and Quit T-Agent app.

**Service control.** By `supervisor` of app.json (`serviceCommand`):

| Supervisor | Start | Restart | Stop |
|------------|-------|---------|------|
| pm2 | `pm2 start <name>`, or `cd <dir> && pm2 start server.js --name <name> --cwd <dir>` when PM2 no longer knows the name | `pm2 restart <name>` | `pm2 stop <name>` |
| launchd | `launchctl bootstrap gui/<uid> ~/Library/LaunchAgents/<label>.plist` when the job is not loaded, then `launchctl kickstart gui/<uid>/<label>` | `launchctl kickstart -k gui/<uid>/<label>` | `launchctl bootout gui/<uid>/<label>` |
| systemd, none, no app.json | instructions (the pm2 command with the install folder, with Copy Command) | not offered | not offered |

The pm2 commands run through the person's login shell (`$SHELL -lc` when it is sh, bash, zsh or ksh, else `/bin/zsh -lc`), after adding `~/.local/bin`, `~/.local/node/bin`, `/opt/homebrew/bin` and `/usr/local/bin` to PATH and loading nvm when pm2 is still not found. Names and paths are single-quoted. Stop and Restart ask for confirmation first, because browsers, phones and linked devices lose the service too. A failed command the person asked for shows its output in an alert; a failed automatic start shows it in the not-running view. The app never starts an unmanaged background process and never kills a process. The output is read as it arrives and taken when the command exits, so the PM2 daemon holding the pipe never blocks it, and a command still running after 90 s is ended.

**Deep links.** The app registers `t-agent://` (CFBundleURLTypes in the bundle) and receives links as `kAEGetURL` Apple Events. The handler is registered in `applicationWillFinishLaunching`, so the link that launched the app is not lost. `t-agent://show` shows the window. `t-agent://open?path=<value>` shows it and loads that path of the server. It is accepted only with exactly one `path` and nothing else, and with no user, port, fragment or path on the host. The value is percent-decoded exactly once (a broken escape or bytes that are not UTF-8 are refused, and `+` stays `+`). It must then start with one `/` (never `//`), have no backslash, whitespace, control or format character, and be at most 4096 characters. The page URL is built from the server's address (non-ASCII is percent-encoded) and must still be of the server's origin. Any other link is ignored. While the server is not running, the path waits and loads when the page shows.

## Self-test

`T-Agent --self-test` (or any build of `apps/macos/*.swift`) runs about 225 checks and prints `ok` / `FAIL` lines and `N passed, M failed`. It exits 0 only when every check passed. It covers app.json (missing, broken, every field, the data home and its overrides), the web addresses, origins and navigation decisions, the links the page hands over (`linkToOpen`), the microphone rule, page URLs, download names, deep links, the exact argv of every service command with shell quoting, the state machine (timing, the one automatic start, failures, timeouts), the monitor run with fake timers / health checks / processes (dropped stale answers, a new address in app.json), the placeholder text, the menu bar entries and their enabling, the alternate items, the main menu's selectors and key equivalents, and the window built offscreen (user agent, gestures, inspector, delegates, the `tagentOpen` handler and what it opens, close hides) and the placeholder layout (8 pt grid, type sizes, the one accent).

Every outside effect is injected (`AppServices`: files, environment, health check, process runner, scheduler, clock, browser opener, pasteboard), so the self-test puts no window on screen, opens no connection, runs no process and never reads the real `~/.tagent`. The window in the test uses a non-persistent website data store and no frame autosave, so nothing is written to the app's defaults or WebKit folders. `test/mac-app-swift.test.js` compiles the sources with `-Onone` into a temporary folder (no warnings allowed), runs the self-test and `--version`, and checks that every source file is in `apps/macos/README.md`, that top-level code is only in `main.swift` and that the folder has no CJK text. It is skipped off macOS or without `swiftc`, and `TA_SKIP_SWIFT_APP=1` skips it on a Mac.

SDK differences: the app never relies on `URL(string:)` refusing a string. Built with the macOS 14 SDK or later, it re-encodes a broken escape (`%ZZ` becomes `%25ZZ`) instead of returning nil, so a check that passed with the 13.3 SDK (T01) failed on K01 (v2.139.1). Broken escapes are found by `hasBrokenPercentEscape` in `URLPolicy.swift` (used by `serverPageURL`; deep links decode with `percentDecodeOnce`), and the self-test checks the helper directly.

What only a person running the app can check: the window and its remembered frame, typing in the terminal (Esc, Tab, arrows, Ctrl keys, an input method), Cmd+C / V / X / A / Z in the page and the terminal, swipe back and forward, the microphone prompt and voice input, file inputs, `confirm` sheets, downloads into `~/Downloads`, links opening in the default browser, `t-agent://` links from the floating window or `open t-agent://...`, the menu bar icon in light and dark menu bars, the Option-click alternate items, Start / Restart / Stop against the real PM2 or launchd (with nvm or Homebrew PATHs), the automatic start at launch, the login cookie surviving an app restart, and the Web Inspector default.

## Building and installing

> Code: `scripts/build-mac-app.js` (build, sign, install; `npm run build:mac-app`), `scripts/mac-app/make-icon.swift` (draws the icon at build time), `lib/swift-toolchain.js` (finds swiftc, shared with the T-Attention desktop window launcher). Tests: `test/mac-app-build.test.js`.

The app is built with the command line tools only (no Xcode project, no committed binary art) into `dist/T-Agent.app` (`dist/` is git-ignored). The person runs the build; the service's install (`install.sh`, `bootstrap.sh`) and update (`services/update-manager.js`) never do, and `build-mac-app.js` is a development-only script in `test/production-dependencies.test.js` (it needs only Node built-ins anyway).

- **Options.** `--arch x86_64|arm64` builds one architecture (default: both, universal). `--install` builds, then installs. `--icon-preview <file>` also copies the 1024 px icon there. `--help`.
- **swiftc.** Found by `findSwiftToolchain`: `/usr/bin/xcode-select -p` must name a developer folder, then `/usr/bin/xcrun --find swiftc` gives the real path and `xcrun --sdk macosx --show-sdk-path` the SDK, passed to swiftc as `SDKROOT`. The `/usr/bin/swiftc` stub is never run (on a Mac without the tools it opens the install dialog). Missing: "swiftc was not found. Install the Xcode command line tools: xcode-select --install".
- **Compile.** Sources: every `apps/macos/*.swift`, sorted by name (main.swift must be there; the icon tool lives outside that folder so it is never compiled into the app). Per architecture: `swiftc -O -swift-version 5 -target <arch>-apple-macos12.0 -framework AppKit -framework WebKit <sources> -o <tmp>/T-Agent-<arch>`. The architectures and the icon build run at the same time. A failed architecture is named ("Could not build for arm64:" and the compiler's error lines; the same error for every architecture is shown once), and when another one built, the message offers `npm run build:mac-app -- --arch <that one>`. Then `lipo -create -output Contents/MacOS/T-Agent <both>` (one architecture: a plain copy).
- **Icon.** `scripts/mac-app/make-icon.swift` is compiled for the host (`-Onone`) and run with `<tmp>/AppIcon.iconset`; it draws with CoreGraphics in sRGB on a 1024 grid: a rounded square 824 x 824 at 100 (the standard macOS margin, corner radius 185) with a gradient from #232733 at the top to #14161c, a soft drop shadow and a faint light edge, a bold white "T" made of two rounded rectangles (no font needed) and a #5b8cff accent dot at the foot of the stem ("T."). It writes the ten files `icon_16x16.png` ... `icon_512x512@2x.png` (16 to 1024 px), and `iconutil -c icns` makes `Contents/Resources/AppIcon.icns`.
- **Bundle.** `Contents/MacOS/T-Agent`, `Contents/Info.plist`, `Contents/Resources/AppIcon.icns`, `Contents/PkgInfo` (`APPL????`). Info.plist is XML written by the script (`infoDictionary`) and checked with `plutil -lint`: CFBundleIdentifier `local.t-agent.app`, CFBundleName / CFBundleDisplayName / CFBundleExecutable `T-Agent`, CFBundlePackageType `APPL`, CFBundleShortVersionString and CFBundleVersion = `app_version` of VERSION.json, CFBundleIconFile `AppIcon`, CFBundleURLTypes (scheme `t-agent`), LSMinimumSystemVersion `12.0`, LSApplicationCategoryType `public.app-category.developer-tools`, NSHighResolutionCapable, NSMicrophoneUsageDescription "T-Agent uses the microphone for voice input.", NSPrincipalClass `NSApplication`, CFBundleDevelopmentRegion `en`, CFBundleInfoDictionaryVersion `6.0`, and NSAppTransportSecurity NSAllowsLocalNetworking (the page is plain http on 127.0.0.1 or the local network). No camera text, no entitlements, not sandboxed.
- **Signature and checks.** `codesign --force --deep --sign - --timestamp=none` (ad hoc), then `codesign --verify --strict` and `lipo -archs` (must list exactly the built architectures).
- **Self-test.** When the host architecture was built, `Contents/MacOS/T-Agent --self-test` runs (2 minutes at most) with `TAGENT_HOME` and `T_AGENT_DATA_DIR` set to a temporary folder, and must exit 0; its `N passed, M failed` line is printed. It is skipped, with a message, when the sources do not contain `--self-test` (such an app would open its window: the GUI is never launched by the build) or when only the other architecture was built.
- **Atomic result.** Intermediate files go to a temporary folder (removed at the end); the bundle is staged in `dist/.build-<pid>/` and only after every check passed renamed over `dist/T-Agent.app` (the old one is moved aside first and deleted). A failed build leaves the previous bundle as it was.
- **Install.** `--install` copies the bundle to `~/Applications/T-Agent.app` (the folder is created when missing; never `/Applications`, never sudo): a copy to `~/Applications/.T-Agent.app.install-<pid>`, then a rename into place. An existing `~/Applications/T-Agent.app` is replaced only when its Info.plist (XML, or binary through `plutil -convert xml1`) has the bundle id `local.t-agent.app`; anything else there stops the install with "... exists but is not this app (bundle id ...). Move it away, then install again." Then `xattr -dr com.apple.quarantine` on the copy ("No such xattr" is fine), and it prints `open ~/Applications/T-Agent.app` and that the web service keeps running when the app quits. `TA_MAC_APP_HOME` replaces the home folder (tests only); development and tests never install into the real `~/Applications`.
- **Timing** (Intel Mac, Swift 5.8): about 2 s for a one-file app with a warm module cache; the first arm64 build on a Mac fills swiftc's module cache (about 50 s).
- **Tests.** `test/mac-app-build.test.js` runs the script against fake `xcode-select`, `xcrun`, `swiftc`, `lipo`, `codesign`, `plutil`, `iconutil` and `xattr` (Node scripts that record their argv and write the expected files): exact argv per architecture, the layout, Info.plist read back, the version, `--arch`, the self-test rules, the atomic replace, the install with an injected home and its bundle id guard, and the error messages. One real build of a stand-in main.swift in a temporary folder (universal, `lipo -archs`, `codesign --verify`, the 1024 px preview, and an install into a temporary home) runs on macOS with the tools, unless `TA_SKIP_SWIFT_APP` is set.

## Server and floating window integration

> Code: `services/app-info.js` (app.json, the web addresses, the installed app), `server.js` (`startAppInfo`, at listen time), `routes/system.js` (`GET /api/system/app-info`), `services/frp.js` and `services/ssh-tunnel.js` (`status()`), `scripts/h5-shell/MacApp.jsx` (the Settings card), `widgets/macos/PartB-Actions.swift` (`appOpenLink`, `openPage`, `raisePage`). Tests: `test/app-info.test.js`, `test/attention-widget-open-terminal.test.js` (the app's page counts as a local page), `scripts/test-h5-mac-app-browser.cjs`, the widget's `--self-test`.

The app is a front end only: the web service is the Node server, which keeps running when the app quits, and browsers, phones and linked devices keep using it as before.

**app.json.** The server writes `<data home>/app.json` (data home of `lib/data-home.js`: `TAGENT_HOME`, then `T_AGENT_DATA_DIR`, else `~/.tagent`) once it listens, and again whenever its content changes: it is rebuilt every 60 s (an unref'd timer) and on each `GET /api/system/app-info`, and written only when something other than `updated_at` changed. The write is atomic (a temporary file in the same folder, then a rename) with mode 0600; the file is not deleted on exit (the app tells a running server by `pid` and a health check of `/api/system/version`). A failing write is logged once and never stops the server. Fields:

- `url`: the loopback address the server answers on (`http://127.0.0.1:<port>` when `HOST` is `0.0.0.0`, `::`, empty or `localhost`; otherwise `http://<HOST>:<port>`, IPv6 in brackets).
- `version`: the `app_version` this process runs (read at listen time). `pid`, `install_dir` (the install folder, `lib/data-home.js INSTALL_DIR`).
- `supervisor`: `pm2`, `systemd`, `launchd` or null, from `lib/update-supervisor.js detectSupervisor` (the same proof-based check as Restart). `pm2_name`: under PM2 the `name` that PM2 copies into the environment of its process (else `pm_id`), null otherwise. `launchd_label`: under launchd the job label launchd sets in `XPC_SERVICE_NAME` (the one `detectSupervisor` trusts), for `launchctl kickstart` / `bootout`; null otherwise (the app then defaults to `com.tagent.client`).
- `updated_at` (ISO), and `addresses: [{ kind, label, url }]`:
  - `local` "This computer": the `url` above.
  - `lan` "Local network (<interface>)": `http://<IPv4>:<port>` for each RFC 1918 address of a non-internal interface (`os.networkInterfaces()`), only when the server listens on every interface (`0.0.0.0`, `::`, empty); listening on one LAN address lists only that one (once: it is also `url`); loopback lists none.
  - `remote`: the public addresses the remote-access features know, each only when real and running: "Remote (frp)" `http://<frp domain or server>:<remote port>` while the frp tunnel runs (its `publicAddress`); "Remote (SSH tunnel)" `http://<ssh host>:<remote port>` while the SSH reverse tunnel runs bound on all interfaces of the server (`bindAll`; bound to the server's loopback it is only reachable through a proxy there, which is not known); "Remote (public page address)" the `publicUrl` of the T-Attention notifier rules (the address messages link to). Service links know only the peer's address, not this one's, so they add nothing.
  - Every URL is `http(s)` with a host and without user name, password, query or fragment (`cleanUrl`), so no token can be written; each URL appears once (the first label wins). No tunnel token, key path or other secret is copied.

**GET /api/system/app-info** (browser session, behind the same login and same-origin gates as the other `/api/system` routes; `Cache-Control: no-store`): `{ addresses, app, server: { version, install_dir } }`. `app` is null when the server is not on macOS; otherwise `{ installed, path, version, matches_server }` for `~/Applications/T-Agent.app`, then `/Applications/T-Agent.app` (`Contents/Info.plist` read with `plutil -convert json -o -`, `CFBundleShortVersionString`; an unreadable plist is installed with version null), cached for 30 s. `matches_server` compares with the running version.

**Settings card.** "Mac app" in Settings → Devices (see "Settings, Devices and Update" in [page-files-and-settings.md](page-files-and-settings.md)): read only, no install button.

**Page channel.** A page loaded in the app's WKWebView on the loopback URL is a top-level page of this machine like a browser tab: `services/page-channel.js` and `GET /api/attention/stream?tab=1` key only on the browser session, `tab=1`, a loopback socket without forwarding headers and a Referer without `pane` (a missing Referer counts), never on the User-Agent, Origin or `Sec-Fetch-*` headers. So the app's page gets `open-terminal` from the floating window's Open session; nothing changed on the server for it.

**Floating window.** With T-Agent.app (bundle id `local.t-agent.app`) installed or running (`NSWorkspace.urlForApplication(withBundleIdentifier:)`, `NSRunningApplication`), each T-Agent page the window opens — the `open_path` fallback of Open session, a Working now row or a bubble, a task link that is a page of this T-Agent, the page root of a bubble without a target — opens as `t-agent://open?path=<path, query and fragment, percent-encoded to unreserved characters>`; an address on any other origin (external task links, a notice's external target) still opens in the browser. When the open-terminal POST was delivered but no tab was focused, the running app is brought forward with `t-agent://show`, else the default browser as before. The lookups are injected (`appInstalled`, `appRunning`, `activateApp`) and never the real ones offscreen; see [attention-desktop-window.md](attention-desktop-window.md).
