# T-Agent macOS app

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

## Building and installing

> Code: `scripts/build-mac-app.js` (build, sign, install; `npm run build:mac-app`), `scripts/mac-app/make-icon.swift` (draws the icon at build time), `lib/swift-toolchain.js` (finds swiftc, shared with the T-Attention desktop window launcher). Tests: `test/mac-app-build.test.js`.

The app is built with the command line tools only (no Xcode project, no committed binary art) into `dist/T-Agent.app` (`dist/` is git-ignored). The person runs the build; the service's install (`install.sh`, `bootstrap.sh`) and update (`services/update-manager.js`) never do, and `build-mac-app.js` is a development-only script in `test/production-dependencies.test.js` (it needs only Node built-ins anyway).

- **Options.** `--arch x86_64|arm64` builds one architecture (default: both, universal). `--install` builds, then installs. `--icon-preview <file>` also copies the 1024 px icon there. `--help`.
- **swiftc.** Found by `findSwiftToolchain`: `/usr/bin/xcode-select -p` must name a developer folder, then `/usr/bin/xcrun --find swiftc` gives the real path and `xcrun --sdk macosx --show-sdk-path` the SDK, passed to swiftc as `SDKROOT`. The `/usr/bin/swiftc` stub is never run (on a Mac without the tools it opens the install dialog). Missing: "swiftc was not found. Install the Xcode command line tools: xcode-select --install".
- **Compile.** Sources: every `apps/macos/*.swift`, sorted by name (main.swift must be there; the icon tool lives outside that folder so it is never compiled into the app). Per architecture: `swiftc -O -swift-version 5 -target <arch>-apple-macos12.0 -framework AppKit -framework WebKit <sources> -o <tmp>/T-Agent-<arch>`. The architectures and the icon build run at the same time. A failed architecture is named ("Could not build for arm64:" and the compiler's error lines; the same error for every architecture is shown once), and when another one built, the message offers `npm run build:mac-app -- --arch <that one>`. Then `lipo -create -output Contents/MacOS/T-Agent <both>` (one architecture: a plain copy).
- **Icon.** `scripts/mac-app/make-icon.swift` is compiled for the host (`-Onone`) and run with `<tmp>/AppIcon.iconset`; it draws with CoreGraphics in sRGB on a 1024 grid: a rounded square 824 x 824 at 100 (the standard macOS margin, corner radius 185) with a gradient from #232733 at the top to #14161c, a soft drop shadow and a faint light edge, a bold white "T" made of two rounded rectangles (no font needed) and a #5b8cff accent dot at the foot of the stem ("T."). It writes the ten files `icon_16x16.png` ... `icon_512x512@2x.png` (16 to 1024 px), and `iconutil -c icns` makes `Contents/Resources/AppIcon.icns`.
- **Bundle.** `Contents/MacOS/T-Agent`, `Contents/Info.plist`, `Contents/Resources/AppIcon.icns`, `Contents/PkgInfo` (`APPL????`). Info.plist is XML written by the script (`infoDictionary`) and checked with `plutil -lint`: CFBundleIdentifier `local.t-agent.app`, CFBundleName / CFBundleDisplayName / CFBundleExecutable `T-Agent`, CFBundlePackageType `APPL`, CFBundleShortVersionString and CFBundleVersion = `app_version` of VERSION.json, CFBundleIconFile `AppIcon`, CFBundleURLTypes (scheme `t-agent`), LSMinimumSystemVersion `12.0`, LSApplicationCategoryType `public.app-category.developer-tools`, NSHighResolutionCapable, NSMicrophoneUsageDescription "T-Agent uses the microphone for voice input.", NSPrincipalClass `NSApplication`, CFBundleDevelopmentRegion `en`, CFBundleInfoDictionaryVersion `6.0`, and NSAppTransportSecurity NSAllowsLocalNetworking (the page is plain http on 127.0.0.1 or the local network). No camera text, no entitlements, not sandboxed.
- **Signature and checks.** `codesign --force --deep --sign - --timestamp=none` (ad hoc), then `codesign --verify --strict` and `lipo -archs` (must list exactly the built architectures).
- **Self-test.** When the host architecture was built, `Contents/MacOS/T-Agent --self-test` runs (2 minutes at most) with `TAGENT_HOME` and `T_AGENT_DATA_DIR` set to a temporary folder, and must exit 0; its `N passed, M failed` line is printed. It is skipped, with a message, when the sources do not contain `--self-test` (such an app would open its window: the GUI is never launched by the build) or when only the other architecture was built.
- **Atomic result.** Intermediate files go to a temporary folder (removed at the end); the bundle is staged in `dist/.build-<pid>/` and only after every check passed renamed over `dist/T-Agent.app` (the old one is moved aside first and deleted). A failed build leaves the previous bundle as it was.
- **Install.** `--install` copies the bundle to `~/Applications/T-Agent.app` (the folder is created when missing; never `/Applications`, never sudo): a copy to `~/Applications/.T-Agent.app.install-<pid>`, then a rename into place. An existing `~/Applications/T-Agent.app` is replaced only when its Info.plist (XML, or binary through `plutil -convert xml1`) has the bundle id `local.t-agent.app`; anything else there stops the install with "... exists but is not this app (bundle id ...). Move it away, then install again." Then `xattr -dr com.apple.quarantine` on the copy ("No such xattr" is fine), and it prints `open ~/Applications/T-Agent.app` and that the web service keeps running when the app quits. `TA_MAC_APP_HOME` replaces the home folder (tests only); development and tests never install into the real `~/Applications`.
- **Timing** (Intel Mac, Swift 5.8): about 2 s for a one-file app with a warm module cache; the first arm64 build on a Mac fills swiftc's module cache (about 50 s).
- **Tests.** `test/mac-app-build.test.js` runs the script against fake `xcode-select`, `xcrun`, `swiftc`, `lipo`, `codesign`, `plutil`, `iconutil` and `xattr` (Node scripts that record their argv and write the expected files): exact argv per architecture, the layout, Info.plist read back, the version, `--arch`, the self-test rules, the atomic replace, the install with an injected home and its bundle id guard, and the error messages. One real build of a stand-in main.swift in a temporary folder (universal, `lipo -archs`, `codesign --verify`, the 1024 px preview, and an install into a temporary home) runs on macOS with the tools, unless `TA_SKIP_SWIFT_APP` is set.
