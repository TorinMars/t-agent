# The page: T-Attention

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

## T-Attention on the page

The page part of T-Attention (branch `feat/todo-ui`; the data, API, CLI, listeners and notifiers are described in the "T-Attention" section). Files: `scripts/h5-shell/Attention.jsx` (panel, rows, edit view), `attention-model.mjs` (pure logic: groups, order, the "Needs you" count, change events, reminders, links, the PATCH body; `test/attention-model.test.js`), `attention-feed.mjs` (list, live stream, reminders, actions), `AttentionSettings.jsx` (the Settings group) and `attention-slots.mjs` (the slot for other parts' settings).

- **Button**: "Attention" (`#h5-attention`, Ant Design `carry out`) in row 2 between Docs and the next-session button; `aria-label` = `title` = "Attention", with the count while some tasks wait for the user ("Attention (2)"). A MUI `Badge` (warning colour, at most `99+`, hidden at 0) shows the number of `waiting_user` tasks. Pointer layout: the same button in the compact action row. The button opens the panel on a phone and shows / hides it on a wide screen (`ui.actions.toggleAttention`).
- **State**: `state.attention` = `{ open, status: idle | loading | ready | error, items, needs, live, focus }`, written only by `attention-feed.mjs` (started once in `entry.jsx`, so the badge and the reminders work before the panel was ever opened). It reads `GET /api/attention?include_done=1&limit=200` at start, follows `GET /api/attention/stream` (`?tab=1` for this machine's stream of the top page: `hello` gives the stream id, reported with `POST /api/attention/stream/seen` on connect when visible, on becoming visible and on window focus; `open-terminal` calls `ui.actions.openTerminalLink` of h5.js, which runs `openTerminalFromLink` in place, without a reload) with `EventSource` (event `change`: `{ kind, item, previous, event }`, applied with `applyChange`; an older copy never replaces a newer one) and reads the list again on every (re)connection and when the page becomes visible. A connection the browser gave up on (HTTP error) is opened again after 1, 2, 5, 10, 30, then every 60 s; the panel says "Not live: reconnecting…" meanwhile. A server without the API leaves the list in its error state ("Could not read the tasks", Try again) and shows no badge.
- **Every engine in one list** (page side of the remote T-Attention; the proxy routes `/api/remote-servers/:id/attention*` and the capability are in the "T-Attention" section). The list holds the items of this machine and of every connected service of the one task list, each item staying on its owner.
  - Engines: `attentionEngines(state.sources)` in `attention-model.mjs`. `h5.js` `publishSources` now also gives each source `listed` (in the task list: known and not hidden by "Show in task list"; false for all until the services and what is hidden are known), `instanceId` and `capabilities` (the `/info` capabilities it already reads, `null` until read; it publishes again when they change). Taken: the listed ones, and of those the remote ones only when online and advertising `attention:remote`, in task list order (this machine first). Before the list is known, and whenever nothing would be left, this machine alone. The feed follows `state.sources`: an engine linked, removed, hidden, shown, gone offline or back is added or dropped (its stream closed, its items removed).
  - Feed (`attention-feed.mjs`): one entry per engine with its own list read (`GET <base>?include_done=1&limit=200`, base `/api/attention` or `/api/remote-servers/:id/attention`, `baseOf`), stream (`EventSource` on `<base>/stream`), reconnects (1, 2, 5, 10, 30, 60 s), reads on every (re)connection and when the page is shown. Items are tagged `engine` (the h5.js key: `local`, `remote:7`) and `key` (`<engine>:<id>`, `tagItem`), since ids repeat between engines; `item.source` stays the reporter. `state.attention` adds `engines` (`[{ key, local, label, name, instanceId, host, ready }]`), `failed` (`[{ key, name }]`, only with more than one engine) and `noMove` (a list of engine keys); `host` is this machine's. `status` is ready once any engine answered; `live` means every engine that answered is connected. An engine whose list fails (502 offline, an error) shows a muted line "Could not load <engine name>" at the top of the list while the others go on; its list is read again 1, 2, 5, 10, 30 then every 60 s and when its stream reconnects (this machine keeps the old behaviour: the error state with Try again when it is the only one). An engine answering 501 / `ATTENTION_REMOTE_UNSUPPORTED` is left out without a word until its capabilities change. The list's `instance_id` (also of this machine) colours the tag when h5.js does not know one; an older server without it works as before.
  - Model: every function names an item by `keyOf` (`key`, else `id` for an untagged list) and a `parent_id` always means an item of the same engine (`buildTree`, `childrenOf`, `descendantsOf`, `parentChoices` of its own engine only, `moveLocal` and `stepMove` among its own engine's rows, `applyChange`, `rollbackItems`). `groupItems(items, { engines })`: inside a group one block per engine in that order (this machine first), each by `sort_order` DESC. Collapsed parents are remembered by id for this machine and by key for another engine (`collapseId`, `readCollapsed`).
  - Rows: with more than one engine every row has the engine tag of the task list in front of its title (`DeviceTag`, now exported from `TaskDrawer.jsx`, unchanged there: name cut to 8 characters, colour from the instance id); the edit view shows it beside "Edit task" and in its meta line. With one engine nothing is added. Rows carry `data-key` and `data-engine` (`data-id` stays the id).
  - Actions take the item's key and go to its engine: the circle, Confirm / Reject / Handled, Save, Delete (409 `HAS_CHILDREN` as before), history, Refresh of the summary, Move up / down / to top, the drag. The drag moves a row only among the rows of its own engine at its level (`peers` filtered by `data-engine`): over another engine's rows its slot stays at the nearest edge of its own block, so the drop is `{ before | after }` of a row of its own engine. A drop on a group title changes the status on the owner (`{ position: 'top', status }`). An engine without `/move` loses the drag of its rows only.
  - Quick add: this machine by default; when more than one engine has a list, a small native select "on <engine>" (`#h5-attention-add-on`, `aria-label` "Add on", 44px tall, at most 120px wide) sends `POST` to the chosen engine; the choice is remembered in `localStorage['h5-attention-add-on']` (none for this machine) and falls back to this machine when that engine leaves the list. Engines whose list failed are not offered.
  - Reminders and the badge count every engine. A reminder of another engine names it: "<Status>: <title> (K01) — <reason>".
  - Context card: `onThisMachine` compares `context.host` with the `host` of the item's own engine. "Open terminal" of another engine's item opens that task's terminal on that engine through `ui.actions.openRow('<engine>|<task id>', …)` when the task is in the one task list (`jumpBack(…, { sourceKey, tasks: state.taskList.tasks })`), else Copy resume command. Its files open on that engine when it reads any path (`ui.actions.canOpenAnyPath(key)` / `openAnyPath(path, key)` in `h5.js`, capability `fs:read-any`), else only their paths show.
  - Test: `scripts/test-h5-attention-remote-browser.cjs` (mocked routes, a fake `EventSource` per stream: two engines merged with tags and repeating ids, a live change of the remote stream with "(K01)", every action on the owner's URL, the drag kept in its engine's block, a title drop on the remote, quick add on another engine, a hidden device left out and back, a failed engine's line, an old engine left out (no capability, or 501), an offline one never read; phone 390 / 320, 1440 mouse, Chinese, and one engine with no tags); `test/attention-model.test.js` (keys, engines, groups, trees, moves, collapse, jump back).
- **One design on both layouts**: the side panel of a computer and the page of a phone show the same header, the same sections and rows, the same empty state and the same edit view; only the container and the way out differ. Header (`<header>`, 56px): the title "T-Attention" in `h6` (`#h5-attention-title`) and a `body2` line with the counts (`#h5-attention-counts`, "Needs you: N · Open: M": `waiting_user` and `review`, and every task that is not done, failed or cancelled; empty while loading and with no tasks) and, while the stream reconnects, " · Not live: reconnecting…" in the warning colour (`#h5-attention-state`, empty when live). On a phone the back arrow (`#h5-attention-close`, "Back") comes first; on the side panel the close button (the same id, "Close") comes last. Then the quick add, the list (the Home view below, on both layouts) and its states: the empty state (`#h5-attention-empty`: the `attentionDone` icon at 48px in `text.disabled`, "No tasks yet" in `subtitle1`, a `body2` hint) and the error state (`#h5-attention-error`, the same layout with "Try again"). Type comes from the theme: row titles `body1`, detail and result lines `body2`, the meta line and the pills `caption`, section headings `overline` (500) with the section's count (`.h5-attention-group-count`). Test: the parity part of `scripts/test-h5-attention-browser.cjs` reads the header, the sections with labels and counts, every row's status, detail line, row buttons, link and title size, and the edit view's fields and actions at 390px and at 1440px and requires them to be equal.
- **Panel**: phone (under 900px) a full-screen `Drawer` that comes in from the right like a page (`#h5-attention-sheet`, a MUI modal: Escape, the back arrow and the Android back button close it, `back.mjs`); wide a floating side sheet over the page (a persistent right `Drawer` whose paper is MD2 elevation 16: the theme's `shadows[16]` and the dark theme's 14.5% white overlay of that elevation, no border; 8px from the top, right and bottom edges of the window, `min(480px, 100vw - rail - 16px)` wide, 8px corners (`DIALOG_RADIUS`); z-index `modal - 10`, above the page, the columns view and the rail, below menus, dialogs and notices; `SIDE_SHEET` in `Attention.jsx`). It changes no layout: the single view, the columns view, the chat and the bottom row keep their full width while it is open (no reflow, no terminal refit, no PTY resize; until v2.139 `html[data-side-panel]` and `--h5-side-width` ended the page and the columns where the panel started). No scrim: a transparent layer under the sheet covers the whole window (`.h5-attention-outside`, `OutsidePress`), so a press anywhere outside closes the sheet and does nothing else: it does not click, focus or type into what lies below, a column's iframe included. The layer stays until the press has ended (pointerup and click; 400ms more after a touch, for its late click). The rail lies under it too, so its Attention button closes the sheet with that one press, as a toggle. Menus and dialogs opened from the sheet (the edit view, the delete confirmation, Reject) lie above the layer, so they are not outside; a press on their backdrop closes only them. The layer also takes the mouse wheel while the sheet is open, as a MUI menu's invisible backdrop does. Escape inside it or with nothing focused (`h5.js`) closes it (an open dialog inside it first), so does the close button; then the focus goes back to what had it when the sheet opened (`opener` in `attention-feed.mjs`: the rail button, or the terminal after the More menu), if that is still there and the focus has not moved elsewhere. Keys typed inside it never reach the terminal, and the back button sees it as a layer (`extra` in `entry.jsx`). One at a time on a wide screen: opening it closes the file viewer and the file tree, opening those closes it. The panel is mounted the first time it opens (`Lazy`).
- **List: the Home view** (both layouts; before the single-view redesign only the phone had it and the side panel had the groups Needs you, Review, Working, To do, Done & failed). The same view as the "Home view" of the t-attention skill and `t-attention list --tree`, with the same grouping (`homeGroups` in `attention-model.mjs` on top of `lib/attention-home.js`, see the `tree` command above): the sections Needs you (waiting_user, then review), Working and To do, each heading with an 8px coloured dot drawn with a `Box` (`error.main`, `success.main`, `warning.main`; theme colours, no emoji), its label (`.h5-attention-group-label`) and the number of tasks drawn in it (`.h5-attention-group-count`); an empty section keeps its heading with "None" (`.h5-attention-none`). Each section holds whole trees (`data-group` `needs_you` / `working` / `todo`; a sub-task is never drawn away from its parent, so there is no "↳" hint here). A row: the circle, the engine tag (several engines), the title, the section's detail line (`homeDetail`; Needs you: what you need to do, the pending text or the reason, for a review with neither "Waits for your confirmation"; a row of another status there shows nothing; Working: the custom status and the first line of the notes, joined by " · "; To do: nothing), the result line for Review and Done (a server with sub-tasks), then a line with the status pill (`.h5-attention-status`, the row's own status: Needs you warning, Review info, Working and Done success, Failed error, else neutral), the time of the last change (`shortTime`, `MM-DD HH:MM` local, the full time in `title`), the source badge, the priority and the due date; the row buttons below. Last, "Done: N" (grey dot, `#h5-attention-closed-toggle`; N = done, failed and cancelled): a tap unfolds the finished tasks (the closed group of `groupItems`, drawn with `buildTree`), except those already drawn in a section as the parent of an open task, so they can be opened or reopened. Collapse, row buttons, drag and drop work as below: a row moves among its siblings of the same engine and the same status group (the server keeps one order per status, and a level of the phone list can hold several statuses), and a drop on a section heading whose statuses do not include the row's sets the heading's first status (Needs you gives waiting_user, Done gives done). An older server (no `parent_id`) gets one row per task in the section of its status.
- **List** (both layouts): quick add at the top (`#h5-attention-add-input`, Enter or the `plus` button, `POST /api/attention { title }`, at most 300 characters); then the Home view sections above (`groupItems` still makes the closed group behind "Done: N"). Inside a section: `sort_order` (highest first, ties by the highest id), the server's order; items of an older server (no `sort_order`) keep the old order: priority (high, medium, low, none), then due date (earliest first, none last), then `updated_at` (newest first). Priority is still shown on the row. A row: the circle (44px, "Mark as done" / "Mark as not done"; a tap sends `PATCH { status: 'done' }` from any status, or `{ status: 'todo' }` on a done task), the title (two lines), the section's detail line, then the meta line: the status pill, the time, the source badge (not for `user`), the priority and "Due YYYY-MM-DD" (red when overdue). Texts from agents are drawn as text, never as markup.
  - Row link: a task whose `link_url` passes `safeLink` has a link button at the right end of its row, before the collapse button (`RowLink`, `.h5-attention-row-link`, the `link` icon at 18px; 44px on touch through the theme's `MuiIconButton` rule; the title keeps the rest of the row, about 170px at 320px). It is a real `<a href>`, so a middle click, "open in a new tab" and a long press (the row's `WebkitTouchCallout: none` is set back to `default` on it) work: an `http(s)` address opens in a new tab (`target="_blank"`, `rel="noopener noreferrer"`), a page path `/…` in this tab. Its `aria-label` and `title` are the `link_label`, else "Open link". A tap stops there (`stopPropagation`: it never opens the edit view), and it never starts a drag (`ignore` of `attentionDrag`). A row without a link, or with one `safeLink` refuses (`javascript:`, `//host`, …), has no button.
- **Rows of a session** (a task from a T-Agent session opens that session on a tap; mockups `AttentionJump.dc.html` and `AttentionJumpDesktop.dc.html` of the coldesign set). `sessionOf(context, { sourceKey, groups, tasks, localHost })` in `attention-model.mjs` (`test/attention-model.test.js`) gives the session of a row whenever `jumpBack` would open a terminal: `{ taskId, terminalId, title, agent, status, device }`, else null. No new request: it reads `state.taskList` (the session rows of the task, when its sessions are listed, and `sessionStates` of the task row, which `h5.js` `taskRow` now adds: the activity feed's terminals that are not idle, `{ <terminal id>: 'running' | 'waiting' }`, null before any activity is known).
  - Session chip in the meta line after the status pill (`.h5-attention-session`, `data-terminal`, `translate="no"`): the terminal glyph (`terminalKeyboard`, 14px), the device tag of the task row (`DeviceTag`, only when the task list shows tags), the session's name in the task list (`.h5-attention-session-name`; for a folded task, whose sessions are not listed, the agent of the context, "Claude" / "Codex", else "Session") and a 6px state dot (`.h5-attention-session-dot`, `data-state` running / waiting / idle with the task list's colours and `title` "Running" / "Needs you" / "Idle"; none while no activity is known). 24px high, primary at 12% (24% on the shown row), `caption` 500.
  - A click, tap, Enter or Space on the row (`.h5-attention-open`, now with `data-session`) opens the session: `ui.actions.openRow(taskId, { kind: 'terminal', id })`, the same as "Open terminal" of the edit view (which stays), also for another engine's item (its `<engine>|<task id>` ref). The task's status is not changed and nothing is sent. The row's accessible name is "<title>, open session <name>".
  - Details stay one step away: an info button at the end of such a row, before the fold button (`.h5-attention-details`, Ant Design `info-circle`, 20px, `aria-label` = `title` = "Details", its own Tab stop) opens the edit view. With a mouse it is transparent until the pointer is over the row or the focus is inside it (its place is kept, so nothing moves); on a touch screen it is always shown, 44px. It never starts a drag (`ignore` of `attentionDrag`). The side panel ends with the hint "Click a row with a session chip to open it · (i) for details" (`#h5-attention-hint`) while an open row has a session.
  - Rows without a session open the edit view as before: no `context.tagent` (added by hand, the CLI outside T-Agent), another machine, the task not in the one list, or the session gone. Gone (`sessionGone`): the task's sessions are known (listed, not loading, no error) and the terminal is not among them; that row has no chip and `jumpBack` gives "Copy resume command" when there is one. A folded task's sessions are not known, so its rows keep the chip; a tap then opens the task with that terminal as asked.
  - The row buttons (circle, Handled, Confirm, Reject, the link, the fold button) are outside the row's button and act on their own.
  - Way back. Phone: the T-Attention page closes (the bottom navigation shows Sessions), the session opens and the notice "Opened from T-Attention: <title>" has a Details action (the notice's one action, see `toast.md`) that opens the page again with that task's edit view (`openAttention({ item: key })`). Computer: the side sheet stays open over the session, no notice; the row of the shown session (`isShownSession` against `state.shownTarget`, now one of the panel's store keys in `App.jsx`) is marked with MD2's selected look (primary at 8%, a 3px primary indicator at the left, `data-shown`, `aria-current` on its button) and the mark follows the shown session, wherever it was changed.

- **Sub-tasks, row buttons and drag** (the page side of the SELF-ATTENTION merge; data and `/move` in the "T-Attention" section). Only for a server whose list items have the `parent_id` key (`hasTree`); an older server gets no tree, no custom status or result and no drag (the row buttons below work there too), and a server that answers `/move` with 404 / 405 sets `state.attention.noMove`, which removes the drag and the drop targets.
  - Tree (`buildTree`, `visibleRows`): inside a group a sub-task is drawn directly under its parent when the parent is in the same group (depth first, siblings in the group order), 16px more indent per level and a thin guide line under the parent's circle, at most 4 levels of indent (`MAX_INDENT` = 3), deeper ones drawn at that indent. A sub-task whose parent is in another group is a top-level row of its own group with a small "↳ <parent title>" line above its title; an unknown parent is a plain row; a cycle in the data never loops. A parent has a collapse button at the right end (`treeChevron`, `aria-label` = `title` = "Collapse sub-tasks" / "Expand sub-tasks", `aria-expanded`, the number of sub-tasks while collapsed), remembered per task in `localStorage['h5-attention-collapsed']` (a JSON list of ids; default expanded).
  - Row: the custom status is part of the Working detail line (no pill); the result line is `result` for Review and Done (when set); the 44px circle stays. Text buttons under the row: Review "Confirm" (`PATCH { status: 'done' }`) and "Reject" (a small `xs` form dialog `#h5-attention-reject` with an optional reason, Cancel and Reject as text buttons, Enter rejects, then `PATCH { status: 'working', attention_reason: null, activity: { kind: 'note', text: 'Rejected: <reason>' } }`, or `'Rejected'` without one); Needs you "Handled" (`PATCH { status: 'working', attention_reason: null, activity: { kind: 'note', text: 'Handled' } }`). One request per task at a time (a double tap sends one); the change is drawn at once and put back with "Could not update the task: <message>" when it fails (`rollbackItems`: only the touched tasks, unless a newer copy arrived meanwhile).
  - Drag (`useListDrag`, now shared in `scripts/h5-shell/list-drag.jsx` with the task and session lists of `TaskDrawer.jsx`; the spec is `attentionDrag` in `Attention.jsx`): a row is held (a finger 400 ms, moving more than 8px first scrolls; a mouse held 400 ms or moved 4px) and moves among the rows drawn at its own level of its group (its siblings), its sub-tasks with it (the floating copy carries them); the circle, the collapse button and the row buttons never start a drag; a plain tap still opens the edit view and the click after a drag is swallowed. The title of every other group (and the folded "Done: N" button) is a drop target (`targets` / `dropOn` of the hook): under the pointer it is tinted and dashed and shows "→ <Status>" at its right end, the copy turns see-through and the row goes back to its place. A drop among siblings sends `POST /api/attention/:id/move { before: <the row now below> }` (or `{ after: <the last sibling> }`); a drop on a title `{ position: 'top', status: <the group's first status> }` ("Done & failed" gives done). The list is drawn at once (`moveLocal`: the moved task's `sort_order` between its new neighbours, or above all of them with the new status) and the answer's `item` and `items` replace the copies (`attentionMove` in `attention-feed.mjs`); a failure slides the rows back (the FLIP of the hook) with "Could not move the task: <message>". Rows slide, the edges auto-scroll and `prefers-reduced-motion` makes it instant, as in the task list.
  - Keyboard: the edit view has "Move up", "Move down" and "Move to top" (`stepMove`, among the siblings; disabled where it cannot go) and the Parent select.
  - Live changes of a move: the server publishes every task whose order or status changed as its own `updated` change with `reorder: true` (the moved task first, with its stored event; the renumbered neighbours with `event: null` and their old `updated_at`, which `applyChange` still accepts, since only an older copy is refused). Reminders are unchanged, but a change of the order alone is never one (`reminderFor` skips a `reorder` change unless its event is a status change, and an update without `previous` is compared with the page's copy).
- **Edit view** (tap on a row): a MUI `Dialog` in the one dialog pattern (`page-dialogs.md`; an `sm` dialog on a wide screen, full screen on a phone, `#h5-attention-edit`), a form whose paper is the `<form>`: the title row ("Edit task" in `h6`, the engine tag, the close button `#h5-attention-edit-close`), the scrolling content between dividers, and the actions row Delete (`#h5-attention-edit-delete`, error colour, at the start), Cancel (`#h5-attention-edit-cancel`) and Save (`#h5-attention-edit-save`, contained, the submit button: Enter in a one-line field saves). A save error is an inline `Alert` (`#h5-attention-edit-error`). Contents: the reason, Title, Notes, Link (`#h5-attention-edit-link-url`, `type=url`, `inputmode=url`, at most 2000, placeholder "https://… or /path") and Link label (`#h5-attention-edit-link-label`, at most 200), filled from the task, then the saved link as a button (below), Status, Priority (native selects), Due date (`type=date`), with a server with sub-tasks also Custom status (at most 100), Result (at most 500), Parent (a native select: "None" and every task that is not this one or one of its sub-tasks, `parentChoices`; empty fields are sent as null), the move buttons and "Sub-tasks (N)" (links that open each one), source and times, Save (`PATCH` with the changed fields only, `patchFor`; empty notes / due date / link / link label are sent as null, which clears them; the server checks the link, `linkUrl` in `services/attention.js`, and its 400 message shows in the error line, "Could not save: <message>"), Delete (a confirmation dialog, then `DELETE`; a task with sub-tasks is refused with 409 `HAS_CHILDREN` and the view says "Delete or move its sub-tasks first"), and the history (`GET /api/attention/:id`, events newest first: created, status `from → to`, updated fields, actor). Escape and the back button close the confirmation, then the edit view, then the panel.
  - The saved link (`#h5-attention-edit-link`, under the two link fields): `safeLink`, so `http(s)` opens in a new tab with `noopener noreferrer`, a page address `/…` in this tab, and anything else is not shown. It shows what is saved; a changed address is opened from here (or the row) after Save. The link fields need no new server: `link_url` and `link_label` are in the API since the T-Attention core, and the PATCH of another engine's task goes through the same proxy, so a remote engine accepts them as well.
  - Web addresses in texts (`Linked` in `Attention.jsx`, `linkParts` in `attention-model.mjs`): in the read-only texts of the edit view (the reason box, the context card's pending text, AI summary, goal and last reply, and the history lines) every `http://` / `https://` address is a link (`.h5-attention-text-link`, new tab, `rel="noopener noreferrer"`, `translate="no"`, broken anywhere); the text reads exactly as before. `linkParts(text)` returns `[{ text } | { url, text }]`: an address ends at white space, quotes, angle brackets and CJK text or punctuation; trailing `.,;:!?'"` and closing brackets (and the CJK ones) are left out, but a bracket closed inside the address stays; only addresses `new URL` reads as `http(s)` with a host become links, so `javascript:`, `data:`, `mailto:` and a bare `www.` stay text. Inputs and the rows (one-line texts, a tap opens the edit view) are never linkified.
- **Context recall** (the "Page" part of the context recall addition; data in `context` of the item, see the "T-Attention" section):
