# The page: bundles, touch targets and tests

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

## Page bundles and chunks

`scripts/build-page-bundles.js` (`npm run build:h5-shell`, also `build:agent-chat`) builds the shell (`scripts/h5-shell/entry.jsx` → `public/js/h5-shell.js`) and the chat view (`scripts/agent-chat/entry.jsx` → `public/js/agent-chat-ui.js`) in ONE esbuild run with code splitting (`--splitting --format=esm`, `publicPath: /js/`, chunks `public/js/chunks/[name]-[hash].js`). The folder is emptied first, so it holds exactly the current build; commit it with the two entries. `test/page-bundles.test.js` checks the result.

- **What loads at start**: `h5-shell.js` (a few KB: entry.jsx) and three chunks: the first screen (App, header, task list, terminal bar, columns, Update button, dialogs, MUI and Emotion), React with react-dom, and esbuild's helpers; `rewritePage` preloads them (`modulepreload`, "Static asset caching"). esbuild splits by module file and puts each file in the chunk of the set of entries that reach it, so every screen chunk (`screen-*.jsx`) imports `shell-core.mjs`, which imports everything `entry.jsx` imports: then all the first screen's modules have the same set and land in one chunk instead of a dozen small ones. A new import in `entry.jsx` must be added to `shell-core.mjs` too (the test checks it).
- **On demand** (`scripts/h5-shell/lazy-screens.jsx`): Settings (`screen-settings.jsx`: the sheet with Engines, rule sync, linked services, remote access, the plugin market and the notifiers, and the three modules that register parts in the T-Attention group, `PluginSettings.jsx`, `AttentionSkillSettings.jsx`, `AttentionWidgetSettings.jsx`, imported there for that side effect, so every part is registered before the sheet is drawn), the T-Attention panel (`screen-attention.jsx`), the design / file sheet (`screen-design.jsx`) and the file tree (`screen-files.jsx`, with Headless Tree). App.jsx draws the lazy component with the same name and props; it is `React.lazy` inside `Suspense` (nothing is drawn until the chunk is there, then the sheet opens with its animation) and stays mounted once loaded. The T-Attention feed (badge, reminders) stays at start. A chunk is fetched early when the pointer rests on, a finger touches or the focus reaches its button (`preloadOnIntent`, by id: `#h5-tasks-settings`, `#h5-attention`, `#h5-design`, `#h5-commands-docs`, `#h5-files-design`, `#h5-design-files`). A chunk that cannot be loaded closes the screen with the notice "This part of the page could not be loaded. Check the connection and reload the page.": browsers remember a failed module for the life of the page (Chromium fails the same `import()` again at once), so only a reload fetches it. The same holds for a page that stays open across an update (the old chunk names are gone): the silent reload after an update ("Automatic refresh after an update") covers most of these.
  - Usage data (`usage-track.mjs` in the first screen, about 1.8 KB; the recorder `usage-recorder.mjs` is a chunk of its own, loaded only while recording is on; see [usage-data.md](usage-data.md)): the first screen went from 768,371 to 770,166 bytes.
  - The Learn page (`screen-learn.jsx`: `Learn.jsx`, its grading, speech, audio and icons; [learn-english-page.md](learn-english-page.md)) is a chunk of its own; the first screen got only its two destinations and the `learn` icon: 775,336 -> 777,246 bytes.
  - The key feel of the page's own keyboard (`key-feedback.mjs`: the haptic tick and the key bubble, "Key feel" in [learn-english-page.md](learn-english-page.md)) is a chunk loaded at the first key press; `Osk.jsx` keeps only the call: 778,014 -> 778,144 bytes.
  - Task dialogs (`screen-task-dialog.jsx`: `TaskDialogs.jsx`, the delete, working directory, archive and visibility dialogs of a task's menu) became a chunk of their own in v2.138.1: v2.138.0 had brought the first screen to 779,608 bytes, over the 760 KiB budget of `test/page-bundles.test.js`; without them it is 768,371. `App.jsx` draws `TaskDialogScreen` (closed after a failed load with `ui.set({ taskDialog: null })`).
- **Small modules that keep the boundary**: `copy-text.mjs` (`copyText`), `engine-errors.mjs` (`errorLabel` of the Engine endpoints) and `service-links-read.mjs` (`readLinks`) were moved out of `Attention.jsx`, `Engines.jsx` and `ServiceLinks.jsx` (which re-export them): the Update button imports the last two, and one import of a screen's file from the first screen pulls the whole file (and what it imports) into the start chunk.
- **Shared with the chat**: the chat entry reaches React and highlight.js, so they are chunks of their own: React with the first screen (the chat loads nothing more for it), highlight.js with the design sheet's Markdown view (`markdown-view-entry.js`, imported by `Design.jsx`). React and react-dom come from the same `node_modules` in the same build, so the chat and the shell can never run different versions. The chat also works without the shell (a page that loads only `agent-chat.js`, as `scripts/test-agent-chat-browser.cjs` does): it imports the same chunks itself.
- **Browser tests** that draw the shell into a page of their own use `scripts/h5-shell-test-script.cjs` `addShell(page)` (it serves `h5-shell.js` and the chunks on the page's origin and adds the module); `scripts/test-h5-lazy-screens-browser.cjs` covers the lazy screens.
- **Sizes** (minified; gzip -9 / brotli 11), before → after: the first screen `h5-shell.js` 1,066,973 / 331,151 / 269,408 bytes in one file → 708,849 / 226,675 / 190,193 in four files (358 KB raw less; the first-screen chunk 482,587, React 223,079). The chat `agent-chat-ui.js` 932,410 / 286,042 / 236,485 with its own React and highlight.js → 544,792 / 163,643 / 140,991, plus the highlight.js chunk (161,174 / 53,417 / 38,475, shared with the design sheet) and React from the page; a page with the shell loads 705,966 / 217,060 / 179,466 for its first chat (nothing for highlight.js after a document with code). On demand: Settings 224,761 + 30,931 (the part shared with T-Attention) raw, T-Attention 40,084, the design sheet 39,537, the file tree 26,911, the Markdown view 3,666. `markdown-view.js` (share pages) and `mindmap-ui.js` are unchanged. Measured with `scripts/test-h5-assets-browser.cjs`'s setup: the English first load is 13 requests / 371,425 bytes sent (brotli; Chinese 16 / 431,339).

## Bundle size and touch targets

- Bundle (`public/js/h5-shell.js`, `npm run build:h5-shell`): 654 KB raw / 204 KB gzip before, 583 KB / 181 KB after. Four MUI parts are no longer imported:
  - `TextField` is replaced by `scripts/h5-shell/TextField.jsx` (FormControl + InputLabel + OutlinedInput / NativeSelect + FormHelperText, the same ids and classes). MUI's TextField also pulls in Select, Menu, Popover and the filled and standard inputs; the page uses only native selects.
  - The MUI `Tooltip` (and Popper) is gone: icon buttons have the same `aria-label` and `title` (`named` in `common.jsx`); the browser shows the title.
  - `Chip` is replaced by `Pill` in `common.jsx` (a span, or a `ButtonBase` when it has `onClick`).
  - `SwipeableDrawer` is replaced by `Drawer` and a small swipe-down handler on the design / file sheet.
- First render: the sheets and dialogs that are closed at start (settings, terminal / session menu, copy view, design / file sheet, upload, retain link, task dialogs, update dialog) are mounted the first time they open (`Lazy` in `App.jsx`, `opened` in `Update.jsx`) and stay mounted after that, so MUI keeps its closing animation and focus return.
- Touch targets (input mode `touch`, `<html data-input="touch">`): every button, list row, checkbox and text input is at least 44 x 44px. The rule is in the theme (`TOUCH` in `theme.mjs`: MuiButton, MuiIconButton, MuiToggleButton, MuiListItemButton, MuiCheckbox, MuiOutlinedInput), so a new control gets it too. Pointer mode (a computer) keeps the compact sizes. Small-looking controls keep a 44px target with a `::after` (the task filters are 32px high pills with a 44px target). Neighbours have 8px between them where the row has room (task row `⋯` / `+`, the task sheet header, row 1 keys); list rows touch, as in any list.
- Row 2 at 320 and 360px (seven buttons before the file tree; since the file tree eight from 360px, from 380px the rest gaps shrink to fit, see "File tree"; since T-Attention the eighth is Attention and Docs is the one left out under 360px): seven 44px buttons and 8px gaps need 380px. Under 380px (`NARROW` in `Terminal.jsx`) the buttons touch: each takes an equal share of the row (at least 44px at 320px, also with the draft box shown) and is drawn 2 to 3px smaller on each side (`::before`, `--h5-slot-pad`), so the whole share is the target and a gap is still visible. No button moved to an overflow menu and the row does not scroll, so every action stays one tap away and send / translate-and-send stay in place. From 380px the buttons have real 8px gaps. The divider before send cancels one gap, so the draft-shown row fits too.
- Saved commands menu: Escape closes it in the capture phase (on a computer the focus stays in xterm, which stops the keydown of keys it handles, so the old bubble listener never heard it); that Escape is not sent to the terminal. The menu is 300px wide (at most the window minus 16px) and long commands and notes wrap inside it.
- Update dialog: links use the theme's light blue (`primary.light`), readable on the dark paper.
- Update dialog, automatic update: when `update-status` has `auto_update` (older servers do not, and then nothing is shown), a switch "Update automatically when idle" posts to `POST /api/system/auto-update` and shows what the server answered, or an error. It is disabled for non-admins and when `supported` is false, with one line saying why. One status line under it follows `state`: the first reason in `waiting_for`, "Will update at about HH:MM", "Updating…", or the reason it gave up. The page side of the restart is under "Automatic refresh after an update".
- Regression: `scripts/test-h5-touch-targets-browser.cjs` checks at 320, 360 and 390px, in every state (main, draft, saved commands, task sheet, terminal and session menus, settings, update dialog, design sheet), that a 44px circle around the centre of every control lands on that control (`elementFromPoint`), and that rows 1 and 2 have 44px buttons. Inline text links are exempt (WCAG 2.5.8).
