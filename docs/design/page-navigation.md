# The page: navigation rail, bottom navigation, session header and phone drawer

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

The single view (one terminal, the default view) has the navigation language of the columns view since the single-view redesign (2026-11).

## Navigation rail

- `NavRail` in `Columns.jsx`, drawn by `App.jsx` (`#h5-columns-nav`, a `nav` landmark "Views"; the id is kept from the columns view, whose rail it was; the columns view itself is in [page-shell-and-columns.md](page-shell-and-columns.md)): one rail for both views, on the wide layout only, fixed at the left edge, 72px (`NAV_WIDTH`), the whole height, z-index 1260 (above the columns view at 1250 and the full-window mind map, below MUI dialogs and menus at 1300). MD2 navigation rail on the paper colour with the 1dp overlay and a 1px divider. Destinations (`RAIL_DESTINATIONS` / `railDestinations` in `columns.mjs`; `.h5-nav-item`, 72 x 56px, a 24px icon over a caption label): Sessions (`#h5-nav-sessions`, library `code`: the single view; in the columns view it leaves the view), Columns (`#h5-nav-columns`, enters the columns view on its Columns tab, red badge `#h5-nav-needs` of the open columns that need the person, only while the view is shown), Attention (`#h5-nav-attention`, toggles the T-Attention panel on the right, `aria-expanded` and a primary tint while it is open, red badge `#h5-nav-attention-count` with `state.attention.needs`, the count of the bottom area's `#h5-attention`; label "Attention, 1 item needs you" / "Attention, N items need you"), Mind maps (`#h5-nav-maps`, the Mind maps tab of the columns view, entering the view when it is off), Learn (`#h5-nav-learn`, library `read`: the Learn page, `ui.actions.openLearn()`, a page right of the rail over either view at z-index 1255; see [learn-english-page.md](learn-english-page.md)). At the bottom: Update (the page's one updater, `UpdateButton` with `#h5-update` and its red dot, 48px with a 22px icon) and Settings (`#h5-nav-settings`, 48px, library `setting`). The current page (`railView`: Settings while `state.settingsOpen`, else Learn while `state.learnOpen`, else the columns view's tab while it is shown, else Sessions) is in the primary colour with a 3px indicator and `aria-current="page"`. Choosing any destination while Settings is open closes it first (`closeSettings()`); Settings itself opens with `openSettings()`. The Learn page is left the same way (`closeLearn()`) when another destination or Settings is chosen. Each destination (Settings included, Update not) is a Tab stop; Up / Down / Left / Right move between them, wrapping, Home / End go to the first / last (`railKey`); a focus ring on keyboard focus. `ui.actions.showView('sessions' | 'columns' | 'maps')` (Columns.jsx `startColumns`) does the switching. A page that cannot show the columns view (a framed page, a top-level `?pane=`: `state.columns` is null) has no Columns destination and its Mind maps opens the full-window mind map (`openMindmaps`), which starts right of the rail there. The rail stays mounted on a narrow screen with `display: none` (so the updater inside it keeps its one poll across a resize; the phone opens its dialog through `ui.actions.openUpdate`); a pane has no rail. While it is shown `html[data-nav-rail]` sets `--h5-nav-width: 72px`. The old header switch `#h5-columns-open`, the rail's leave switch `#h5-columns-toggle` and its second Update button `#h5-columns-update` are gone.

## Bottom navigation

- `BottomNav.jsx` (`#h5-bnav`, a `nav` landmark "Views", drawn by `App.jsx`): the phone counterpart of the rail, on the narrow layout only and never in a pane (on the wide layout it stays mounted with `display: none`). An MD2 bottom navigation bar fixed at the bottom of the window, 56px plus the bottom safe-area inset, on the paper colour with the 1dp overlay and a divider above, z-index 1150: under MUI's modals (1200 and up), so the task drawer, dialogs, menus and deeper full-screen pages (a plugin page of Settings, for example) lie over it, while the three destination pages end above it and leave it free. Destinations, the rail's model without Columns plus Settings (`phoneDestinations` in `columns.mjs`; `.h5-bnav-item`, a 24px icon over a caption label, sharing the width, at most 168px each): Sessions (`#h5-bnav-sessions`, the terminal page), Attention (`#h5-attention` on a touch screen, so the T-Attention id a phone had on its tool row survives; `#h5-bnav-attention` in pointer input, whose "More tools" menu keeps `#h5-attention`; name "Attention (N)" with a red badge `.h5-attention-badge`, the rail's count), Mind maps (`#h5-bnav-maps`, the full-window mind map), Learn (`#h5-bnav-learn`, the Learn page above the bar) and Settings (`#h5-bnav-settings`). The shown one (`phoneView`: Settings, T-Attention, Learn or the mind map while open, else Sessions) is in the primary colour with `aria-current="page"`. The arrow keys and Home / End move between the items (`railKey`).
- Usable over the modal pages: the bar is a portal, a child of `<body>` of its own, so while a destination is open it removes the `aria-hidden` that MUI's modal puts on the other children of `<body>`, and it stops a `focusin` inside it from reaching the modal's focus trap (which listens on the document), so a focus put on the bar stays there and the arrow keys work. Tab inside a modal page still loops inside it (MUI's sentinels); a keyboard user leaves with Escape or the back arrow, which returns to Sessions, where the bar is in the Tab order.
- One destination at a time (`choosePhoneView`): choosing one closes the page that is open (`closeSettings`, `closeAttention`, `closeLearn`, `ui.actions.closeMindmaps`, which sends a waiting save first) and opens the new one; Sessions closes them all; choosing the shown one does nothing. Each page is a back layer (back.mjs: the modals and the mind map's `mindmapLayers`), so the back button or gesture closes it and Sessions is current again (inside the mind map the editor goes back to the list first; on a group page of Settings back returns to the group list, and from there to Sessions; T-Attention's back arrow returns to Sessions). `state.mindmapOpen` (h5.js `openMindmaps` / `closeMindmaps`) tells the bar the map is open.
- The pages end above the bar: while it is shown `html[data-bnav]` sets `--h5-bnav-space` (56px plus the inset). `.h5-app` keeps that room free at its bottom (its terminal box shrinks, so the terminal refits through its ResizeObserver, and `measureTerminalBox` runs in the same frame); `#h5-bottom` leaves the safe-area inset to the bar. T-Attention (`#h5-attention-sheet`, a page from the right with a back arrow) and Settings (its group list `#h5-settings` and a group's page `#h5-settings-page`, MUI full-screen dialogs) are reached by their ids from `h5.css` only: their modal root ends at the bar and is the containing block of their fixed paper (`transform`; T-Attention's paper gets `max-height: 100%` and no bottom inset). The full-window mind map (`#h5-mindmap`) and the chat (`#h5-agent`) are fitted by h5.js (`bottomNavSpace`, `ui.actions.fitAboveBottomNav` when the bar comes or goes).
- The bar steps aside (`display: none`, `data-bnav` removed) while the terminal's own keyboard is shown (`state.osk`; its room goes to the keyboard and the terminal refits once, as before), while the draft box has the focus (`state.keyboard === 'draft'`) and while the system keyboard is up (`state.softKeyboard`, published by h5.js `fitViewport` from the same test as the keyboard shift: a field that raises a keyboard has the focus and the visual viewport is more than 8px shorter than the tallest height). After the draft box or the system keyboard it comes back 250ms later (`RETURN_MS`), so a tap that blurs the draft box lands before the page moves. While it is away for typing and no system keyboard is up (the draft box focused with a hardware keyboard, and the moment before it comes back) the page keeps its room (`html[data-bnav-room]`), so the terminal keeps its size; with the system keyboard up the room is not kept and h5.js pins the terminal as before. So typing a message never resizes the PTY; only the terminal keyboard (a real change of the layout) refits it. While the task drawer is open it lies under the drawer's scrim and is `inert`.
- Sessions is the terminal page as it was: the header, the terminal, the draft box, row 1 (the function keys, 44px) and row 2 (seven tools in a 48px row; T-Attention left it), see "Touch: the draft box and two rows" in [page-terminal-and-bottom-bar.md](page-terminal-and-bottom-bar.md).

## Page layout

- Wide, left to right: the rail (72px), the task list (304px, foldable with `#h5-sidebar-toggle`; its paper is fixed at `left: var(--h5-nav-width)`), then `#h5-app` (header, terminal, bottom row) and the chat from `calc(var(--h5-nav-width) + var(--h5-sidebar-width))` (`public/css/h5.css`), to the right edge of the window; the T-Attention side sheet floats over it and changes no offset. `terminal-box.mjs` keeps measuring the terminal box (the rail calls `measureTerminalBox()` when it appears), so the top sheets still line up with the terminal. The columns view is `left: NAV_WIDTH` (right of the rail); the T-Attention side sheet floats above it too (z-index `modal - 10`, above the rail) and the view keeps its full width; Settings gets z-index 1255 over the view. The skeleton in `h5.html` has the rail, the 304px sidebar edge and the 48px / 56px header.

## Session header

- `Header.jsx`. Computer: a dense 48px bar (47px + the 1px line) on the paper colour with the 1dp overlay that reads like a column header: the fold toggle, then `#h5-open-tasks` (a click unfolds a folded sidebar; inert while the sidebar is shown) with the state dot of the shown session, its device tag (`#h5-task-service`), "task · session" on one line cut with an ellipsis (`#h5-task-name` subtitle1 500, `#h5-session-name` body2 secondary), then the agent and "running" as a caption, or a warning "Needs you" chip; at the right "Wide terminal" (`WidthButton`, unchanged) and "More" (`#h5-header-more`, `taskMore`, menu `#h5-header-more-menu` with "Refresh the page", `#h5-refresh`). Phone: a 56px MD2 app bar: the menu button `#h5-open-tasks` (`menu`, "Tasks", `aria-haspopup="dialog"`, `aria-expanded`), the task name (subtitle1, 16px medium, one line) over a status line (dot, device tag, session, "· running" / "· needs you"), "Wide terminal" and "More" with "Refresh the page" and "Update" (`#h5-header-update`, with a red dot, also on the More button, while an update waits; it opens the rail's updater's dialog with `ui.actions.openUpdate` and the focus comes back to More). The live state (running / needs you / idle) is the columns view's rule (`columnStatus`) on `state.shownTarget` (`useShownState` in Columns.jsx): the small parts that draw it subscribe to it as a string, so an activity push draws them only when the state changes and never the header (`scripts/test-h5-render-count-browser.cjs`).

## Phone drawer

- `TaskDrawer` in `TaskDrawer.jsx`: an MD2 modal navigation drawer from the left, min(320px, 100vw - 56px) (`--h5-drawer-width`), on the paper colour with the 1dp overlay, square corners, over a 32% black scrim (`#h5-task-backdrop`); the page under it no longer slides right with rounded corners (`body.h5-tasks-open` still marks it open and `App.jsx` still makes the page and the chat inert; back.mjs closes it as any modal). Below the list, only in a narrow pane of the multi-column view (which has neither the bar nor the rail; `DrawerNav`): a divider and labelled 48px rows with a 24px icon, `#h5-tasks-nav`: Mind maps (`#h5-tasks-mindmap`) and Settings (`#h5-tasks-settings`); choosing one closes the drawer first. A phone has those destinations in its bottom navigation and the wide layout in the rail, so their task list has no footer (the T-Attention row `#h5-tasks-attention` is gone). `lazy-screens.jsx` preloads the Settings chunk from `#h5-nav-settings` and `#h5-bnav-settings`, the T-Attention chunk from `#h5-nav-attention` and `#h5-bnav-attention` too (`#h5-attention` was there already) and the Learn chunk from `#h5-nav-learn` and `#h5-bnav-learn`.
