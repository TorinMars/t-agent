# Site library

> Part of the T-Agent design document. The index of all parts is [DESIGN.md](../../DESIGN.md).

The site library is the part of the browser feature (a paired Chrome extension drives the user's own browser through `tcli browser`) that accumulates what the model learns about each website, so capabilities build up over time. One entry per host (like `github.com`), shared across the user's linked devices. Code: `services/browser-sites.js` (storage, validation, redaction, the sync adapters), `routes/browser-sites.js` (the page router and the `tcli site` relay), `scripts/tcli-site.js` (the CLI), `scripts/h5-shell/BrowserSites.jsx` (the Settings viewer), `lib/browser-redact.js` (the redaction rule, shared with the recordings and `tcli browser` on the browser branch), `rules/skills/browser/SKILL.md` (the agent skill).

- **Entry shape** (shared contract section 8): `{ site, title, summary (Markdown, ≤ 256 KiB), pages: [{ pattern, purpose }], actions: [{ name, description, steps: [ text or tcli browser commands ], selectors? }], apis: [{ name, method, url (a template with {param}), description, auth, params, request_example?, response_shape? }], notes, sources: [{ recording_id, at }], updated_at, updated_by (device name), version }`. The entry is **authored content** the model writes from what it saw with `tcli browser`; recordings are not parsed automatically in v1. Size limits are in `services/browser-sites.js` `LIMITS` (the summary ≤ 256 KiB, the whole entry ≤ 1 MiB, bounded counts of pages / actions / APIs). Unknown top-level keys are dropped. The host is normalised to lower case, without a leading `www.`, a scheme, a port or a path.
- **No raw secrets.** Every saved entry is run through the redaction rule (`lib/browser-redact.js`, shared contract section 5): a value under a secret-named key, and any JWT or bearer token, becomes `<redacted:N>`. After that, if a value **still looks like a token** (a known provider key prefix such as `sk_live_…` / `ghp_…`, or a 32+ character high-entropy run that mixes letters and digits) the save is refused with `SITE_HAS_SECRET`, naming the field, so the model replaces it with a placeholder. The library and the sync therefore never carry real credentials.
- **Storage.** `system_state` rows, one per site (`browser_site_v1:<host>`), so there is **no schema bump** (the browser pairing list the core branch keeps in `system_state` for the same reason). A deletion removes the row and records a tombstone in the single row `browser_sites_tombstones_v1` (`{ host: { updated_at, updated_by } }`), so the deletion also travels to linked devices; tombstones older than 180 days are pruned on export. Each entry carries its own sync clock (`updated_at` ms, `updated_by` device name, `version`), stamped so it never goes backwards for a host.
- **Sync** (scope "shared"). The library is a synced setting (`services/settings-sync.js` registry key `browser-sites`): the **whole set** travels inside the same per-link sealed envelope as the other settings, and is **merged per site on import** — last-writer-wins per host (later `updated_at` wins, a tie goes to the greater device name), with tombstones. A `null` from a peer that never had the feature is a no-op, never a wipe (merge, not replace). So two devices that edit **different** sites both keep their entries. The one lossy case is two devices editing different sites within the same clock tick and then never changing anything again: the device that pulled holds the union at once, and the other catches up on its next save or delete (which re-stamps its whole set newer). Entries hold no raw secrets, so syncing them is safe; the server runs redaction again over an incoming entry and drops one that still leaks a token.
- **Routes.** Page (logged in, `GET` / `PATCH` / `DELETE /api/browser-sites[/:site]`, `GET /api/browser-sites/search?q=`): list, read, edit, delete. tcli relay (`/api/tcli/site/*`, the terminal hook token, this machine only, mounted next to `/api/tcli/oss` before the body parsers and the gates; a request without the `X-T-Agent-*` headers or not from this machine is passed on): `GET list`, `GET show?site=`, `POST save` `{ site, entry }`, `POST edit` `{ site, changes }`, `POST rm` `{ site, confirm: true }`, `GET search?q=`. Errors are `{ error, message }` (`INVALID_SITE`, `SITE_TOO_LARGE`, `SITE_HAS_SECRET`, `SITE_NOT_FOUND`, `CONFIRM_REQUIRED`, `UNKNOWN_ROUTE`).
- **CLI.** `tcli site list [--query Q]`, `show <site> [--json]`, `save <site> --file f.md|f.json` (a `.json` file is the whole entry, any other file its Markdown summary), `edit <site> [field=value ...] [--set field=value] [--file F]` (`field` is `title`, `summary` or `notes`; an empty value clears it; `--file` merges a `.json` partial or a `.md` summary), `rm <site> --yes`, `search <text>` (over the host, title, summary, action names / descriptions / steps and API names / URLs / descriptions). Readable output by default, `--json` the raw answer. Exit codes as the other groups.
- **Settings viewer.** "Site library", a part of Settings → Tasks and files (`scripts/h5-shell/BrowserSites.jsx`, `#h5-sec-browser-sites`, scope label "Shared across devices", read each time the group opens): the known sites, each openable to read its summary (shown as Markdown source, never rendered HTML), pages, actions and APIs, with a Delete button. Editing is read-only here; agents write entries with `tcli site`.
- **Agent skill.** `browser` (`rules/skills/browser/SKILL.md`, registered in `services/agent-skills.js`): the accumulation loop — check the library, explore with `tcli browser` (`net` / `record` to discover requests and actions), then write or update a `tcli site` entry, never storing real secrets.
