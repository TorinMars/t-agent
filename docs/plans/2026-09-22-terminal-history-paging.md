# Bounded terminal history restoration

User: terminal reload should initially load only recent lines; older content loaded on demand or silently. Default recent 500 rendered lines, old logs on demand. Preserve live local and remote terminals, ANSI state, alternate screen, input responsiveness, authentication, OSC52 protections and current persisted 5MB retention. Do not truncate raw ANSI arbitrarily.

1. Backend owns bounded state snapshot generation and history paging in routes/terminal.js/lib helper plus remote proxy forwarding if needed, dependencies and backend tests. Prefer matching xterm headless + serialize maintained incrementally per PTY so connection does not replay full log into browser. First history frame remains {type:'history', data:ANSI}, with optional archive:{id,before,hasMore,limit:500}. Archive is a connection-scoped immutable retained raw log snapshot, paging backwards <=500 raw lines and <=128KiB per response. history-page request {type:'history-page', id, before, requestId}; response {type:'history-page', id, before,hasMore,data:plainText,requestId}. Archive starts from end of full retained log; separate viewer is chronological and may include recent lines again. Never send archived ANSI controls to live PTY. Unknown/invalid history controls must be consumed, not forwarded to shell. Older Engines without archive metadata receive no page request. Auth checks apply to all frames. Initial state snapshot limited to recent 500 scrollback lines + visible screen and preserves full-screen state. Legacy history frame remains understood by older Client; new Engines always bounded initial replay. Keep raw persisted log format/schema unchanged.
2. Frontend shared TerminalHistory controller handles history and history-page frames on local/remote sockets, honors clipboard.writeHistory and viewport restore and input pause while initial replay. Header History button enabled only with advertised archive on current connected terminal. On demand readonly dialog shows pages as text, preserves scroll position when prepending, no silent full download, error/disconnection/reconnect/task-switch disposal and bounded loaded text. Preserve text/live output ordering; older engines continue legacy initial replay and show update hint/no pager. No new independent mobile page.
3. Integration root docs, test both local/remote plumbing plus real xterm state/paging regression, full suite and review, patch release/push per AGENTS.md, verify remote images status.
