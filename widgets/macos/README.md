# T-Attention desktop widget (macOS)

A small native window that stays on top of everything and shows three numbers in a small vertical capsule: the unfinished T-Attention tasks, the ones that need you (red) and the agents running now (teal). Point at it and a panel opens with the tasks, where you can confirm, reject, mark as handled, open a task's link, reorder, change status, create, edit and delete them. Notifications that T-Agent sends to this Mac slide out beside it as a small bubble; a click opens their target, and a task's bubble carries its buttons (Confirm, Reject, Handled) and a Reply field that types into the agent's terminal. A task tied to an agent terminal has Open session, the panel shows the agent terminals working now, Ctrl+Option+T opens the panel from the keyboard and Ctrl+Option+N starts a new task. It is a port of the floating window of the earlier SELF-ATTENTION tracker (`task_widget.swift`), now reading T-Agent's widget API, so it shows the tasks of this machine and of every connected Engine.

- `*.swift`: the widget, AppKit only, no dependencies, compiled together. `main.swift` is the entry point (Swift runs top-level code only from `main.swift`) and has the overview comment; every other file holds one `// MARK: -` section of the code, or part of one, so changes to different parts touch different files:

  | File | Section |
  |------|---------|
  | `Strings.swift` | Strings: `L()`, `S()`, the string table, loose JSON values |
  | `Model.swift` | Model: items, engines, the item list |
  | `Notices.swift` | Notices: notices and their queue, the bubble's place, sections, the display order, rows and the summary |
  | `Reordering.swift` | Reordering: moves and drops |
  | `Requests.swift` | Requests: `WidgetAPI`, the form draft |
  | `Views.swift`, `Views-Forms.swift`, `Views-Bubble.swift` | Views: panels, buttons, rows, the background and offscreen render; the task form and the delete question; the notice bubble |
  | `Controller.swift` | Controller: the layout constants and `WidgetController` with all its stored properties, `init` and the app delegate methods |
  | `Controller-Window.swift`, `Controller-Rows.swift`, `Controller-Data.swift`, `Controller-Testing.swift` | The controller's methods as `extension WidgetController`, by its own `// MARK:` groups: collapsed window and detail panel; reordering, menus, form and row actions; timers, data and the notice bubble; offscreen checks and renders |
  | `PartB-Actions.swift` … `PartF-Look.swift` | Parts B (actions and replies), C (live activity), D (shortcuts and preferences), E (one request per tick), F (the panel's look and Open session) |
  | `SampleData.swift`, `SelfTest.swift` | `--render-sample` and `--self-test` |

  Stored properties stay in the class body in `Controller.swift` (an extension cannot have them; a part with much state keeps it in a small object the class holds, like `PartDState`). A member used from another file cannot be `private` (Swift's `private` and `fileprivate` stop at the file), so the controller's members used across files are internal. Any new `*.swift` file in this folder is built with the others; top-level statements belong only in `main.swift`. The name `TAttentionWidget.swift` (the single file of v2.132.0 and older) is never built: an archive update leaves that file behind, see below.
- `strings.json`: every English string the widget shows (a JSON array). T-Agent serves their translations from `GET /api/attention/widget/strings`; the Chinese text is in `public/js/i18n-zh-ui.js`.

## How T-Agent builds and starts it

```bash
swiftc -O -swift-version 5 -framework AppKit widgets/macos/*.swift -o <binary>
TA_WIDGET_URL=http://127.0.0.1:3000 TA_WIDGET_TOKEN=<token> <binary> --parent-pid <server pid>
```

- Build only when the binary is missing, older than the newest source file, made from another set of `.swift` files (the stamp lists them) or by another T-Agent version, into a temporary name first, so a failed build never replaces a working binary. The launcher passes the files sorted by name (`widgetSources` in `services/attention-widget.js`).
- Updating from v2.132.0 or older (one file, `TAttentionWidget.swift`): the old server keeps its old launcher until it restarts. If that launcher runs meanwhile (the switch turned on), a git install has no `TAttentionWidget.swift` any more, so it only sets "The window source is missing from this install" and leaves the running window and the binary alone; an archive install still has the old file (an archive update deletes nothing), so it starts the old binary as before. After the restart the new launcher builds the files of this folder (the version in the stamp changed), never the leftover `TAttentionWidget.swift`, which would define everything a second time. A build takes about 30 s with `-O` (about 10 s with `-Onone`). It needs the Xcode command line tools (`xcode-select --install`); without `swiftc` the server should log one line and keep running.
- `TA_WIDGET_URL`: the server's base address (default `http://127.0.0.1:3000`; anything that is not an `http(s)` URL falls back to it). `TA_WIDGET_TOKEN`: sent as `Authorization: Bearer <token>` on every request. The widget never prints or logs the token.
- With `--parent-pid` the widget exits within a second after the server process goes away, so restarting T-Agent replaces the window.
- Requests use their own `URLSession` with no proxy (`connectionProxyDictionary = [:]`, so `http_proxy` never catches `127.0.0.1`), a 3 s timeout and no cache.

## Behaviour

- **Window**: a vertical capsule of a fixed 32 x 90 pt (corner radius 16), the same for every count, language and state, so the panel and the bubble beside it never move: a borderless non-activating panel at `.statusBar` level, on all Spaces and over full-screen apps, no Dock icon. Drag it to move it; the position is saved in the defaults suite `local.t-agent.attention-widget` for each display (`display_positions`, keyed `uuid:<display UUID>`, else `name:<name>@<frame>`, as fractions of the room left on the display, so a capsule at the right edge stays at the right edge; `display_last` is the display it was last dragged to; the old keys `x`, `y` are still written and read as the fallback; the first start uses 16 pt from the top-right of the main screen, `--no-persist` 16 pt from the bottom-left). When displays are added, removed or rearranged, the capsule goes to the saved spot of the display it was last dragged to when that is connected, else to the saved spot of the display it is on now, always inside the visible frame. A spot saved by the older, smaller pill is clamped with the capsule's size, so it lands on screen. Its tooltip and accessibility label read "12 open · 6 need you · 1 running" (the exact numbers; without a list, why). Right-click offers Quit.
- **Numbers**: three rows of 26 pt, top to bottom, centred, monospaced-digit semibold, no dots or icons: the unfinished tasks (everything but `done`, `failed` and `cancelled`) in the label colour; Needs you in red (`systemRed`): the Needs you section plus the waiting agent terminals that no Needs you item stands for (an item's `session` with the terminal's engine, `task_id` and `terminal_id` is the same thing; the activity lists only this machine's terminals, so an item of another Engine or without a session takes none; each terminal once); the running agent terminals in teal (`systemTeal` in dark mode, a darker teal in light mode for contrast), 0 while `show_activity` is off. Every row is always there: a zero is a dim 0 (38% opacity), above 99 a row shows "99+" at 10 pt (9 pt if needed; numbers are 13 pt, 12 pt if two digits do not fit, with at least 3 pt free on each side). `–` (dim) in the first two rows while T-Agent cannot be reached (or refuses the token); the panel then says why.
- **Refresh**: one request every 5 s, `GET /api/attention/widget/tick?after=<last notice seq>&items=<etag>` (`&activity=0` while the live activity is off), with the item list (`list`, `null` when the window's `etag` is still the server's), the notices, the live activity and the preferences in one answer; one timer tick at a time. After the window's own change it asks at once without the etag, so the list always comes. The list part is applied only while no row is held or dragged, no button is pressed and no move or action is in flight (a list that comes meanwhile is dropped and the etag kept, so the next tick sends it again); a list changed in the window itself (a move) drops the etag. A failure shows like an unreachable T-Agent and hides the activity. A 404 (a T-Agent older than `/tick`): `GET /api/attention/widget/items`, `/notices`, `/activity` and `/prefs` at once and on every 5 s tick, as before, and `/tick` again after 5 minutes. The interface strings are loaded once at start (and tried again with each refresh until they arrive); without them every string is the English text.
- **Panel**: 312 pt wide and at most 440 pt high (it scrolls past that); opens at once on hover and closes 0.3 s after the pointer leaves both windows. It stays while a form, a menu, the delete question or a red message (3 s) is showing. Its top row is "Tasks" with the unfinished count (muted) at the left, and a magnifier (Search) and `+` (New task) as icons at the right.
- **Background** (capsule, panel, forms and bubble): the `.menu` material's blur under a veil of `windowBackgroundColor` at 86% (`backgroundVeil`, `BackgroundVeilView`), so a terminal full of text behind the window shows only as a faint tint and never mixes with the panel's text. The veil follows light and dark.
- **Sections**: each header is a small drawn colour dot, the name and a muted count of its rows ("Needs you  4"; no emoji): Needs you, red (`waiting_user` and `review`), Working, green (`working`), To do, yellow (`todo`, and any status the widget does not know), Finished, grey (`done`, `failed`, `cancelled`): a disclosure header with a triangle at the right, collapsed by default; a click opens it to the rows (kept in the defaults, `finished_expanded`). An engine that could not be read adds a muted line "Could not load <name>".
- **Order inside a section**: one block per engine, this machine first, then the order of `engines` in the answer (an engine not listed after them). Inside an engine block, by `sort_order` (highest first, then the id). In Needs you each engine shows its `waiting_user` rows before its `review` rows, because the server orders and moves those two statuses as separate groups. A child is drawn under its parent with `└` when both are in the same block; otherwise it is an ordinary row of its own section.
- **Rows**: the title alone on the first line (one line, cut with an ellipsis when it does not fit), then at its right end the row's icon buttons and, with more than one engine, a small tag with the engine's name in the colour of `color_index` (the page's tag palette, `TAG_COLORS` in `scripts/h5-shell/task-order.mjs`). Under it, 11 pt and muted, `custom_status` and the first of `pending`, `attention_reason` or `result`, joined with " · ", at most two lines (the second cut with an ellipsis). A sub-task's `└` and indent stay; its second line starts under its title. The row's tooltip and VoiceOver label are the full title and second line. A row is 18 pt with only a title line (16 pt without icons or tag) and about 32 pt with a second line (it was 37 to 73 pt with the text buttons).
- **Buttons**: review rows get Confirm (`POST …/confirm`) and Reject (`POST …/reject`, no reason); `waiting_user` rows get Handled (`POST …/handled`), and Reply after it when the agent's terminal can take one (see Sessions). Every row action is a small icon button (18 pt, an SF Symbol drawn as a template in the secondary label colour; Confirm in the accent colour) at the right end of the title line, before the engine tag, in this order: Open link (`link`), Open session (`terminal`), Confirm (`checkmark.circle.fill`), Reject (`xmark.circle`), Handled (`checkmark.circle`), Reply (`arrowshape.turn.up.left`). Each has the English words as tooltip and accessibility label (from the strings table). A faint square shows under the pointer. SF Symbols need macOS 11; without them (or a missing symbol) the buttons are the earlier grey text pills. In Needs you the icons always show; in Working, To do and Finished they show only while the pointer is over the row (a hidden icon never takes a press), and on every row while VoiceOver runs. Without a mouse every action stays reachable: the row's right-click menu lists Open link, Open session and the row's own actions (Confirm and Reject, or Handled and Reply) before Edit and Delete, and the row is one VoiceOver element whose custom actions are the same actions. They work on the first click while another app is in front. While a request is out the row's buttons are off; on success the list refreshes at once; on failure the buttons come back and "Action failed: …" shows.
- **Links**: a task with a `link_url` gets an Open link button, first among the row's buttons, in every section; its tooltip is `link_label`, else the address, and its accessibility label is "Open link: <label or address>". The row's right-click menu also offers Open link. A click opens the link in the default browser (`NSWorkspace.shared.open`) and sends nothing to T-Agent; it never starts a press or drag of the row, and the button stays on while the row's own action is out. Only an `http(s)` address with a host and without a user name or password, or a page path `/...` (not `//host`, no backslash or whitespace) is a link; a page path opens on `TA_WIDGET_URL`. Anything else (`javascript:`, `file:`, `ftp:` …) shows no button.
- **Sessions**: an item may carry `session` (`{ engine, task_id, terminal_id, agent, live, open_path }`, the agent's terminal of the task); an older server sends none and nothing below shows. `open_path` is used only when it starts with `/?openTerminal=`, has something after it and has no whitespace, control character or backslash. Rows with one get Open session, after Open link, in every section, and the right-click menu offers it too; it stays on while the row's request is out. It does not open a new tab every time (`openTerminalPage`): it first sends `POST /api/attention/widget/open-terminal { engine, task_id, terminal_id }` (read from `open_path`, the pattern the page accepts), and the server tells the most recently used T-Agent page of this machine to switch to that terminal in place (the code path of the `?openTerminal=` link). The answer `{ delivered, focused }`: `delivered` 1 or more means a page switched, and nothing opens; unless `focused` (the T-Agent browser extension brought that tab and its window to the front), the window brings the default browser (the app that opens `http:` addresses) to the front without opening an address (`NSWorkspace.openApplication`, which only activates an app that already runs). `delivered` 0 (no page open), a 404 (a T-Agent older than the route) or any other failure opens `TA_WIDGET_URL` + `open_path` in the default browser as before (also for an item of a connected service; the page opens that terminal itself). A Working now row and a bubble whose click opens a session take the same path. When `engine` is `local` and `live` is `true`, a `waiting_user` row also gets Reply: a small form over the list (heading "Reply to the agent", the task's title, a one-line field, Cancel and Send) that takes the keyboard like the task form. Return or Send posts `POST …/reply { text }` (trimmed, 1 to 4000 characters); success closes it and refreshes the list, a refusal keeps it with its text and shows "Reply failed: <server message>", and a 404 or 409 also reads the list again.
- **Drag to reorder**: press a row and move it; a blue line shows where it lands. A row moves only inside its own engine block and server group, among its siblings (a parent takes its children). The new order shows at once and goes to `POST …/move` with `before_key` / `after_key` (or `position: 'top'` for a drop on the section title); if the server refuses, the rows go back and "Move failed: …" shows. A drop on another machine's row is refused with "Only within the same machine".
- **Drag to change status**: drop a row on another section's title (Needs you → `waiting_user`, Working → `working`, To do → `todo`, the Done line → `done`): `POST …/move` with `position: 'top'` and `status`. The section is outlined with the status it will get. A drop between the rows of another section places it there, within the same engine.
- **Create, edit, delete**: `+` opens a form (Name, Status, Notes) that creates on this machine (`POST …/items` with `engine: 'local'`). Right-click a row for Edit (the same form with Custom status, filled in; Save sends only the changed fields with `PATCH`, and nothing when nothing changed; when the answer has no `notes` for that item the Notes field is left out so it cannot overwrite them) and Delete (asks first; `DELETE`; a refusal such as a task with subtasks shows "Delete failed: <server message>"). Return saves when the name is not empty, Esc cancels; during an input-method composition both belong to the input method. The keyboard goes back to the previous app when the form closes.
- **Notice bubble**: with each 5 s tick the widget also gets the notices (`notices` of the tick, or `GET /api/attention/widget/notices` from an older T-Agent; first `?after` left out, so the server answers the notices of the last 60 s; then `?after=<last seq>`; one request at a time). A seq lower than the last one (the server started again) is taken as the new start, and that answer's notices are shown. A 404 (an older server) stops it quietly for 5 minutes; any other failure is tried again on the next tick. A notice needs a title or a text (a text alone becomes the title); its `target` is used only when it is an absolute `http(s)` address with a host and without a user name or password; `seconds` defaults to 8 when it is missing or not a number from 0 up, 0 keeps it until it is closed, and it is capped at an hour.
  - Place: a borderless non-activating panel (same level and Spaces as the window, never key except while its reply field shows) 280 pt wide, beside the window on the side toward the middle of the screen (left of a window in the right half, else right), its top level with the window's top, inside the visible frame. While the task panel is open the bubble sits beside the window and the panel together, so they never overlap; it moves back when the panel closes, and it follows the window while it is dragged.
  - Look: a dot in the colour of `status` (Needs you orange, review blue, done green, failed red, working teal, anything else and direct or test messages grey), the title in bold (two lines at most), the text (three lines at most), the sender (`from`) small and muted, and a × (tooltip and accessibility label "Close"). The panel's material and corners, light or dark like the panel. It slides out 16 pt and fades in over 0.2 s; with Reduce motion it just appears.
  - Click anywhere but the × and the buttons: for a notice of a task the list has, opens the task's link (the notice's `target`, made from it by the server), else the task's session (as Open session: an open T-Agent page switches to it, else `TA_WIDGET_URL` + `open_path` opens; tooltip "Open session"); otherwise `target`, else the T-Agent page (`TA_WIDGET_URL/`), so a click always leads somewhere; then closes the bubble. The pointer is a hand over it and the tooltip is the address (or "Open session", "Open T-Agent"). The × only closes it.
  - Buttons (text buttons, not icons: there are at most two or three, and words read faster in a notice that waits a few seconds): an `item` notice whose `key` is in the window's item list gets, under its text, the buttons of that task's row by the status the list has now (the list refreshes every 5 s, and a notice that came first gets its buttons then; the bubble grows and keeps its top): review → Confirm and Reject, `waiting_user` → Handled, and Reply when the task's terminal can take one. Confirm, Reject and Handled run the row's code (same request, same "Action failed: …" in the panel on a refusal) and close the bubble without opening anything. Direct and test messages, and tasks the list does not have, get none.
  - Reply: the buttons give way to a one-line field ("Reply to the agent") and Send. Only while it shows can the bubble become key (it takes the keyboard without bringing T-Agent to the front); when it closes the keyboard goes back. Return or Send posts the reply; Esc goes back to the buttons; during an input-method composition both belong to the input method. While the field shows the timer waits (also after the pointer leaves) and a click on the bubble body does nothing. Success closes the bubble; a refusal stays in the bubble in red ("Reply failed: <server message>") with the text kept, and a 404 or 409 also reads the list again. An answer that comes after the bubble was closed with the × shows in the panel.
  - Timing: it closes after `seconds`; the pointer over it pauses that, leaving starts the full time again.
  - Several notices: one bubble at a time, the others wait, oldest first; a newer notice of a task that is already waiting (same `key`) replaces it. When more than three wait as the next one is due, only the newest is shown, with "+N more" under it.
  - VoiceOver: each notice is announced (title and text); the bubble is a button that opens it.
- **Live agent activity**: with each 5 s tick the widget also gets `activity` of the tick (or asks `GET /api/attention/widget/activity`, one request at a time, from an older T-Agent) for the agent terminals of this machine that are running, waiting for a permission answer (`waiting`) or have just finished (`done`). A 404 (an older server) hides it and asks again after 5 minutes; any other failure (or a refused token) hides it until the next answer, so a stale "running" never stays. A terminal needs a `state` of `running`, `waiting` or `done`; `since` is an ISO time (with or without fractions); `agent` counts only as `claude` or `codex`; `open_path` is used only when it starts with `/?openTerminal=` and has no whitespace, control character or backslash.
  - Capsule: the running count is its teal number; the waiting ones (they need you) join its red Needs you number unless a Needs you item stands for the same terminal.
  - Panel: "Working now" at the top, before Needs you, only when there is a terminal (no header otherwise). Waiting terminals first (so they never hide behind "+N more"), then running, then done; inside each the newest `since` first. One line per terminal: a dot in the state's colour, the task title with the agent muted after it (Claude, Codex, else the terminal title, else "Terminal"), and at the right the state (Running, Waiting for you in orange, Finished; a waiting terminal with `waiting_kind` says Needs selection or Needs acceptance instead, same orange) and the time since `since` ("42s", "3m", "1h 2m"), moved on with each tick. At most 5 rows, then "+N more". A click on a row (hand pointer, hover highlight; VoiceOver: a button with "agent, task, state, time") switches an open T-Agent page to that terminal, else opens `TA_WIDGET_URL` + `open_path` in the default browser, as Open session does (see Sessions); a row without a valid path is plain text. Its header is a teal dot, "Working now" and the number of terminals. A change while a row is held or dragged waits for the next tick.
  - `WidgetController.showActivity` (default true) turns it off: no request, no indicator, no section. It is the hook for `show_activity` of `GET /api/attention/widget/prefs`; turning it on asks at once.
- **Search**: the magnifier in the top row (or Cmd+F, or Ctrl+Option+T) opens a small field in place of the "Tasks" heading; it stays open while it has text and closes with the panel (or a click on the magnifier while it is empty). It filters every section by title, notes and custom status (case, diacritics and full or half width ignored; each word of the query must match; Chinese works as one word). Sections without a match say "No matches"; the Finished group shows its matching rows even when collapsed. Clicking the field or Cmd+F (while the panel has the keyboard) gives the panel the keyboard and keeps it open; Esc clears the search, a second Esc closes the panel, and so does a click in another app. Rows are not reordered while a search filters them.
- **Shortcuts**: Ctrl+Option+T opens the panel and keeps it open with the keyboard in the search field (the other app stays frontmost) until Ctrl+Option+T again, Esc or a click elsewhere; Ctrl+Option+N opens the New task form. Carbon `RegisterEventHotKey`, no Accessibility permission. A shortcut taken by another app is reported once on stderr.
- **Fade when idle**: after 30 s without the pointer over the capsule, without the panel or a bubble showing and without a rise of its red Needs you number, the capsule fades to 45% opacity (0.8 s; at once with Reduce motion); the pointer, a new notice, a shortcut or more Needs you tasks bring it back.
- **Preferences**: `prefs` of every tick (`{ hotkeys, dim_when_idle, show_activity }`, the switches of the settings card; from an older T-Agent `GET /api/attention/widget/prefs` at start and every 5 s); changes apply live. A 404 (an older T-Agent) means all on, tried again after 5 minutes; any other failure keeps what is in effect. `show_activity` is `showActivity` for the live activity section.
- Keys contain `:` and are percent-encoded in request paths. Error answers are `{ error, message }`; the widget shows `message`.

## Testing rules

The widget runs on the user's desktop. When working on it:

- Never put a window on the user's screen: do not run a built widget without `--self-test` or `--render-sample`, and do not take screenshots of the screen (no full-screen `screencapture`). Look at the panel through `--render-sample DIR`, which renders it offscreen.
- Never register the global shortcuts in a test: `--self-test` and `--render-sample` never call `RegisterEventHotKey` and install no event monitors.
- No CGEvent or other system-level input injection. The self-test sends its mouse events in-process to the views; the real pointer never moves.
- Compile test binaries outside the repository (a temporary or scratch folder), never next to the source.
- Never touch the live defaults suite `local.t-agent.attention-widget` (the self-test and the renders never read or write it).
- `test/attention-widget-swift.test.js` checks `strings.json` against all the `.swift` files and the Chinese dictionary everywhere, that top-level statements are only in `main.swift`, and on macOS with `swiftc` compiles the files the launcher builds to a temporary folder (`-Onone`) and runs `--self-test` (skipped elsewhere; `TA_SKIP_SWIFT_WIDGET=1` skips it on a Mac).
- What only a person can check (no automated test reaches it): typing into the bubble's reply field (the bubble taking and giving back the keyboard, the cursor over the field), the hand pointer and hover highlight on Working now rows, real hover and the 0.3 s close, the row icons appearing under the pointer and their hover square, the blur under the veil over real windows, Open session switching a real browser tab and the extension or the window bringing it to the front, the bubble's slide, its shadow and the hand pointer over it, the VoiceOver announcement, a real mouse drag of rows and of the window, right-click menus, keyboard focus going back to the previous app, typing with an input method, staying on top over full-screen apps and on every Space; the global shortcuts (and the stderr line when another app holds one), Esc and the click elsewhere that close a pinned panel, Cmd+F, the fade animation, and the capsule moving between displays when they are plugged in or out.
