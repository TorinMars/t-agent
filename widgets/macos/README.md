# T-Attention desktop widget (macOS)

A small native window that stays on top of everything and shows how many T-Attention tasks are unfinished, with a red badge for the ones that need you. Point at it and a panel opens with the tasks, where you can confirm, reject, mark as handled, open a task's link, reorder, change status, create, edit and delete them. Notifications that T-Agent sends to this Mac slide out beside it as a small bubble; a click opens their target, and a task's bubble carries its buttons (Confirm, Reject, Handled) and a Reply field that types into the agent's terminal. It is a port of the floating window of the earlier SELF-ATTENTION tracker (`task_widget.swift`), now reading T-Agent's widget API, so it shows the tasks of this machine and of every connected Engine.

- `TAttentionWidget.swift`: the whole widget. One file, AppKit only, no dependencies.
- `strings.json`: every English string the widget shows (a JSON array). T-Agent serves their translations from `GET /api/attention/widget/strings`; the Chinese text is in `public/js/i18n-zh-ui.js`.

## How T-Agent builds and starts it

```bash
swiftc -O -swift-version 5 -framework AppKit widgets/macos/TAttentionWidget.swift -o <binary>
TA_WIDGET_URL=http://127.0.0.1:3000 TA_WIDGET_TOKEN=<token> <binary> --parent-pid <server pid>
```

- Build only when the binary is missing or older than the source, into a temporary name first, so a failed build never replaces a working binary. A build takes about 30 s with `-O` (about 10 s with `-Onone`). It needs the Xcode command line tools (`xcode-select --install`); without `swiftc` the server should log one line and keep running.
- `TA_WIDGET_URL`: the server's base address (default `http://127.0.0.1:3000`; anything that is not an `http(s)` URL falls back to it). `TA_WIDGET_TOKEN`: sent as `Authorization: Bearer <token>` on every request. The widget never prints or logs the token.
- With `--parent-pid` the widget exits within a second after the server process goes away, so restarting T-Agent replaces the window.
- Requests use their own `URLSession` with no proxy (`connectionProxyDictionary = [:]`, so `http_proxy` never catches `127.0.0.1`), a 3 s timeout and no cache.

## Flags

| Flag | Effect |
|------|--------|
| `--parent-pid PID` | Exit when `PID` is no longer this process's parent (checked every second) |
| `--no-persist` | Neither read nor write the saved window position |
| `--self-test` | Run the checks (grouping, order, children, every request with its headers and body, links and the Open link button, notices and the bubble (reading, polling, place, clicks, timing, queue), the live activity (reading, order, open paths, elapsed times, polling, the pill indicator, the Working now rows and their clicks, `showActivity`), the bubble's buttons and reply field, sessions (reading, the open path, Open session) and the panel's reply form, edit diffs, drag targets including cross-machine refusals, the form and its input-method handling, string fallback) in-process, without putting a window on screen and without the network. Prints `ok   …` / `FAIL …` lines and `N passed, M failed`; exits 0 only when every check passed |
| `--render-sample DIR` | Build the widget and the panel with built-in sample data (three engines, children, every row type, rows with links, a failed engine), render them offscreen into `DIR/*.png` (light and dark, mid-drag, a refused drop, the forms, the delete question, unreachable, and `bubble-*.png`: the notice bubble beside the window, light and dark, for a task that needs you (with Handled and Reply), a direct message, five notices at once, a review task with Confirm and Reject (`bubble-actions-*`), the reply field typed (`bubble-reply-*`) and refused (`bubble-reply-failed.png`), and `reply-form-*.png`: the panel's reply form, and `widget-activity-*.png` / `panel-activity-*.png`: the pill and the panel with live agent activity, light and dark, and the pill with only a waiting terminal; it prints the pill's width with activity) and exit. No window is ever put on screen |

## Behaviour

- **Window**: a small pill, 26 pt high and as wide as it needs (38 pt at least, about 70 pt with a two-digit count and badge): a borderless non-activating panel at `.statusBar` level, on all Spaces and over full-screen apps, no Dock icon. Drag it to move it; the position is saved in the defaults suite `local.t-agent.attention-widget` (keys `x`, `y`; the first start uses 16 pt from the top-right of the main screen, `--no-persist` 16 pt from the bottom-left). Its width changes only between drags; in the right half of the screen it grows to the left, so the right edge stays put. The word "Tasks" is its tooltip and accessibility label, not drawn. Right-click offers Quit.
- **Count**: the unfinished tasks (everything but `done`, `failed` and `cancelled`); the red badge to its right counts the Needs you section and is hidden at zero. `–` while T-Agent cannot be reached (or refuses the token); the panel then says why.
- **Refresh**: `GET /api/attention/widget/items` every 5 s, paused while a row is held or dragged, a button is pressed, or a move or an action is in flight. The interface strings are loaded once at start (and tried again with each refresh until they arrive); without them every string is the English text.
- **Panel**: 288 pt wide and at most 440 pt high (it scrolls past that); opens at once on hover and closes 0.3 s after the pointer leaves both windows. It stays while a form, a menu, the delete question or a red message (3 s) is showing.
- **Sections**: 🔴 Needs you (`waiting_user` and `review`), 🟢 Working (`working`), 🟡 To do (`todo`, and any status the widget does not know), ⚪ Done: N (`done`, `failed`, `cancelled`, a count only). An engine that could not be read adds a muted line "Could not load <name>".
- **Order inside a section**: one block per engine, this machine first, then the order of `engines` in the answer (an engine not listed after them). Inside an engine block, by `sort_order` (highest first, then the id). In Needs you each engine shows its `waiting_user` rows before its `review` rows, because the server orders and moves those two statuses as separate groups. A child is drawn under its parent with `└` when both are in the same block; otherwise it is an ordinary row of its own section.
- **Rows**: the title, then `custom_status` as a muted suffix, and a second line with the first of `pending`, `attention_reason` or `result`. With more than one engine each row has a small tag with the engine's name in the colour of `color_index` (the page's tag palette, `TAG_COLORS` in `scripts/h5-shell/task-order.mjs`).
- **Buttons**: review rows get Confirm (`POST …/confirm`) and Reject (`POST …/reject`, no reason); `waiting_user` rows get Handled (`POST …/handled`), and Reply after it when the agent's terminal can take one (see Sessions). They sit at the right of the row's second line when the title takes one line and the second line leaves room; otherwise on a line of their own under the text. Without a second line, they sit at the right of a title that leaves room for them (left of the engine tag). They work on the first click while another app is in front. While a request is out the row's buttons are off; on success the list refreshes at once; on failure the buttons come back and "Action failed: …" shows.
- **Links**: a task with a `link_url` gets an Open link button, first among the row's buttons, in every section; its tooltip is `link_label`, else the address, and its accessibility label is "Open link: <label or address>". The row's right-click menu also offers Open link. A click opens the link in the default browser (`NSWorkspace.shared.open`) and sends nothing to T-Agent; it never starts a press or drag of the row, and the button stays on while the row's own action is out. Only an `http(s)` address with a host and without a user name or password, or a page path `/...` (not `//host`, no backslash or whitespace) is a link; a page path opens on `TA_WIDGET_URL`. Anything else (`javascript:`, `file:`, `ftp:` …) shows no button.
- **Sessions**: an item may carry `session` (`{ engine, task_id, terminal_id, agent, live, open_path }`, the agent's terminal of the task); an older server sends none and nothing below shows. `open_path` is used only when it starts with `/?openTerminal=`, has something after it and has no whitespace, control character or backslash. Rows with one get Open session, after Open link, in every section, and the right-click menu offers it too: it opens `TA_WIDGET_URL` + `open_path` in the default browser (also for an item of a connected service; the page opens that terminal itself), sends nothing to T-Agent and stays on while the row's request is out. When `engine` is `local` and `live` is `true`, a `waiting_user` row also gets Reply: a small form over the list (heading "Reply to the agent", the task's title, a one-line field, Cancel and Send) that takes the keyboard like the task form. Return or Send posts `POST …/reply { text }` (trimmed, 1 to 4000 characters); success closes it and refreshes the list, a refusal keeps it with its text and shows "Reply failed: <server message>", and a 404 or 409 also reads the list again. When a row's buttons do not fit one line, Open link and Open session go on a line above the task's actions.
- **Drag to reorder**: press a row and move it; a blue line shows where it lands. A row moves only inside its own engine block and server group, among its siblings (a parent takes its children). The new order shows at once and goes to `POST …/move` with `before_key` / `after_key` (or `position: 'top'` for a drop on the section title); if the server refuses, the rows go back and "Move failed: …" shows. A drop on another machine's row is refused with "Only within the same machine".
- **Drag to change status**: drop a row on another section's title (Needs you → `waiting_user`, Working → `working`, To do → `todo`, the Done line → `done`): `POST …/move` with `position: 'top'` and `status`. The section is outlined with the status it will get. A drop between the rows of another section places it there, within the same engine.
- **Create, edit, delete**: `+` opens a form (Name, Status, Notes) that creates on this machine (`POST …/items` with `engine: 'local'`). Right-click a row for Edit (the same form with Custom status, filled in; Save sends only the changed fields with `PATCH`, and nothing when nothing changed; when the answer has no `notes` for that item the Notes field is left out so it cannot overwrite them) and Delete (asks first; `DELETE`; a refusal such as a task with subtasks shows "Delete failed: <server message>"). Return saves when the name is not empty, Esc cancels; during an input-method composition both belong to the input method. The keyboard goes back to the previous app when the form closes.
- **Notice bubble**: with each 5 s refresh the widget also asks `GET /api/attention/widget/notices` (first `?after` left out, so the server answers the notices of the last 60 s; then `?after=<last seq>`; one request at a time). A seq lower than the last one (the server started again) is taken as the new start, and that answer's notices are shown. A 404 (an older server) stops it quietly for 5 minutes; any other failure is tried again on the next tick. A notice needs a title or a text (a text alone becomes the title); its `target` is used only when it is an absolute `http(s)` address with a host and without a user name or password; `seconds` defaults to 8 when it is missing or not a number from 0 up, 0 keeps it until it is closed, and it is capped at an hour.
  - Place: a borderless non-activating panel (same level and Spaces as the window, never key except while its reply field shows) 280 pt wide, beside the window on the side toward the middle of the screen (left of a window in the right half, else right), its top level with the window's top, inside the visible frame. While the task panel is open the bubble sits beside the window and the panel together, so they never overlap; it moves back when the panel closes, and it follows the window while it is dragged.
  - Look: a dot in the colour of `status` (Needs you orange, review blue, done green, failed red, working teal, anything else and direct or test messages grey), the title in bold (two lines at most), the text (three lines at most), the sender (`from`) small and muted, and a × (tooltip and accessibility label "Close"). The panel's material and corners, light or dark like the panel. It slides out 16 pt and fades in over 0.2 s; with Reduce motion it just appears.
  - Click anywhere but the × and the buttons: for a notice of a task the list has, opens the task's link (the notice's `target`, made from it by the server), else the task's session (`TA_WIDGET_URL` + `open_path`, tooltip "Open session"); otherwise `target`, else the T-Agent page (`TA_WIDGET_URL/`), so a click always leads somewhere; then closes the bubble. The pointer is a hand over it and the tooltip is the address (or "Open session", "Open T-Agent"). The × only closes it.
  - Buttons: an `item` notice whose `key` is in the window's item list gets, under its text, the buttons of that task's row by the status the list has now (the list refreshes every 5 s, and a notice that came first gets its buttons then; the bubble grows and keeps its top): review → Confirm and Reject, `waiting_user` → Handled, and Reply when the task's terminal can take one. Confirm, Reject and Handled run the row's code (same request, same "Action failed: …" in the panel on a refusal) and close the bubble without opening anything. Direct and test messages, and tasks the list does not have, get none.
  - Reply: the buttons give way to a one-line field ("Reply to the agent") and Send. Only while it shows can the bubble become key (it takes the keyboard without bringing T-Agent to the front); when it closes the keyboard goes back. Return or Send posts the reply; Esc goes back to the buttons; during an input-method composition both belong to the input method. While the field shows the timer waits (also after the pointer leaves) and a click on the bubble body does nothing. Success closes the bubble; a refusal stays in the bubble in red ("Reply failed: <server message>") with the text kept, and a 404 or 409 also reads the list again. An answer that comes after the bubble was closed with the × shows in the panel.
  - Timing: it closes after `seconds`; the pointer over it pauses that, leaving starts the full time again.
  - Several notices: one bubble at a time, the others wait, oldest first; a newer notice of a task that is already waiting (same `key`) replaces it. When more than three wait as the next one is due, only the newest is shown, with "+N more" under it.
  - VoiceOver: each notice is announced (title and text); the bubble is a button that opens it.
- **Live agent activity**: with each 5 s refresh the widget also asks `GET /api/attention/widget/activity` (one request at a time) for the agent terminals of this machine that are running, waiting for a permission answer (`waiting`) or have just finished (`done`). A 404 (an older server) hides it and asks again after 5 minutes; any other failure (or a refused token) hides it until the next answer, so a stale "running" never stays. A terminal needs a `state` of `running`, `waiting` or `done`; `since` is an ISO time (with or without fractions); `agent` counts only as `claude` or `codex`; `open_path` is used only when it starts with `/?openTerminal=` and has no whitespace, control character or backslash.
  - Pill: right of the counts, a small teal dot with the running count (the dot fades in and out; it stays still with Reduce motion), and an orange badge with the waiting count (they need you, like the red Needs you badge). Hidden at zero. The pill stays 26 pt high; with two-digit counts, a Needs you badge, running and waiting it is about 124 pt wide. VoiceOver reads "2 running, 1 waiting for you".
  - Panel: "Working now" at the top, before Needs you, only when there is a terminal (no header otherwise). Waiting terminals first (so they never hide behind "+N more"), then running, then done; inside each the newest `since` first. One line per terminal: a dot in the state's colour, the task title with the agent muted after it (Claude, Codex, else the terminal title, else "Terminal"), and at the right the state (Running, Waiting for you in orange, Finished) and the time since `since` ("42s", "3m", "1h 2m"), moved on with each tick. At most 5 rows, then "+N more". A click on a row (hand pointer, hover highlight; VoiceOver: a button with "agent, task, state, time") opens `TA_WIDGET_URL` + `open_path` in the default browser, which opens that terminal on the T-Agent page; a row without a valid path is plain text. A change while a row is held or dragged waits for the next tick.
  - `WidgetController.showActivity` (default true) turns it off: no request, no indicator, no section. It is the hook for `show_activity` of `GET /api/attention/widget/prefs`; turning it on asks at once.
- Keys contain `:` and are percent-encoded in request paths. Error answers are `{ error, message }`; the widget shows `message`.

## Testing rules

The widget runs on the user's desktop. When working on it:

- Never put a window on the user's screen: do not run a built widget without `--self-test` or `--render-sample`, and do not take screenshots of the screen (no full-screen `screencapture`). Look at the panel through `--render-sample DIR`, which renders it offscreen.
- No CGEvent or other system-level input injection. The self-test sends its mouse events in-process to the views; the real pointer never moves.
- Compile test binaries outside the repository (a temporary or scratch folder), never next to the source.
- Never touch the live defaults suite `local.t-agent.attention-widget` (the self-test and the renders never read or write it).
- `test/attention-widget-swift.test.js` checks `strings.json` against the source and the Chinese dictionary everywhere, and on macOS with `swiftc` compiles the widget to a temporary folder (`-Onone`) and runs `--self-test` (skipped elsewhere; `TA_SKIP_SWIFT_WIDGET=1` skips it on a Mac).
- What only a person can check (no automated test reaches it): typing into the bubble's reply field (the bubble taking and giving back the keyboard, the cursor over the field), the pulse of the activity dot (offscreen renders show it still), the hand pointer and hover highlight on Working now rows, real hover and the 0.3 s close, the bubble's slide, its shadow and the hand pointer over it, the VoiceOver announcement, a real mouse drag of rows and of the window, right-click menus, keyboard focus going back to the previous app, typing with an input method, staying on top over full-screen apps and on every Space.
